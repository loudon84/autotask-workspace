# Engine 门户会话缓存 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SOP 任务之间复用已登录的供应商门户 cookies，避免每个任务重新 OCR 登录。

**Architecture:** 保持现有 `MANAGED` + `CLOSE_ON_FINISH`（每次 Run 仍关浏览器进程）。在 Engine 本机按 `normalize(portalUrl) + login username` 缓存 Playwright `storage_state.json`。启动时注入 cookies；登录成功后写回；同键互斥，禁止两个 Playwright 同时写同一份状态。不启用 `PERSISTENT_PROFILE`，不改 Task Binding。

**Tech Stack:** rpa-engine Playwright storage_state、asyncio + 文件锁、pytest。

---

## 已定规则

- 缓存键 = 规范化门户 URL + 登录账号（不是业务主体，不是门户记录 id）。
- 同 URL 不同登录（芯云 vs 国际）必须分开。
- 演示 `192.168.102.247:3000` 与正式 `supplier.tiandy.com` 因 URL 不同自然隔离。
- 两个门户记录若 URL+登录相同，共享缓存是正确行为。
- 同一 `(url, login)` 不能并发写入：Run 全程持锁。
- 浏览器进程仍关闭；只留 cookies 文件。密码不进键、不进 `meta.json`、不进日志。

## 行为

1. 规范化：小写 scheme/host；去 fragment；去尾斜杠；去默认端口 80/443。
2. 磁盘：`runtime-cache/sessions/<sha256>/storage_state.json` + `meta.json`（url、username，无密码）。
3. 登录失败 `SRM_LOGIN_FAILED` / `SRM_CREDENTIALS_MISSING`：删除该键。
4. 验证码类失败：不覆盖已有文件（避免把登录页 cookies 写成“已登录”）。
5. 其它成功/失败：覆盖写入，供下一任务跳过 OCR。
6. 损坏的 state 文件：丢掉，空会话启动。

## 验收

- 芯云test 连续两个任务（如扫单 → 填交期）：第二个日志出现 `reusedSession: true`，不再 OCR。
- 同机国际账号（不同登录）不串会话。
- Engine 仍 `CLOSE_ON_FINISH`；重启 Engine 后 cookies 文件仍在，下一任务可复用。
