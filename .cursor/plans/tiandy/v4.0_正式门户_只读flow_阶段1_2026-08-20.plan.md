# v4.0 正式门户只读 Flow（阶段 1）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为正式 SRM（`https://supplier.tiandy.com`）单独出三套只读 Flow 包并只绑到「天地伟业-国际-正式演练」，使登录、扫单、收货查询、回签探测能在正式站跑通；演示门户绑定不动。

**Architecture:** 演示门户与正式门户地址不同、DOM 不同。演示包只用 `data-rpa`；正式包只用正式站可见文案/占位符/`.el-table`，禁止带 `data-rpa`。同一 workflow code 用**不同版本号**区分环境，禁止一个版本绑两个门户。Hash 路由以探测为准：订单 `#/order/list`、收货 `#/order/receivingList`（演示是 `#/supplier/orders`）。验证码正式站是 data-URL PNG，无固定文件名映射 → 未知验证码走 `HUMAN_VERIFICATION_REQUIRED`。本阶段不设 `dryRun`（只读）。

**Tech Stack:** rpa-flows 版本目录 + pytest；Engine Registry 上传/校验/发布；service `WorkflowBinding` 只写正式门户。

**Spec:** [project-docs/prd/AutoTask v4.0 天地伟业正式演练.md](../../project-docs/prd/AutoTask%20v4.0%20天地伟业正式演练.md)

**红线：** 不点保存/签章/生成对账单/提交审批；演示 Binding 不改 URL、不切正式版；凭据不进 Git/文档/日志。

## 探测结论（选择器依据）

正式站无 `data-rpa`。登录：placeholder「账号或手机号码 / 验证码」、`input[type=password]`、协议「用户注册协议」、按钮「登录」。登录后 `#/dashboard`，顶栏「订单」。订单列表 `#/order/list`，表头含订单编号、回复状态。收货 `#/order/receivingList`，对账状态含「未提交」。样例已回签 PO：`POJS2607170008`。待签章计数 0 → 扫单空列表算 SUCCESS。

`login_success` 不能用 `[data-rpa='portal-env-tag']`。正式用顶栏订单菜单：`.el-menu-item:has-text('订单'):visible, span:has-text('订单'):visible`。

订单行/详情无 `data-rpa='order-row-{po}'`。正式回签探测：按表头找「订单编号」列，点该行「详情」类按钮；详情页回复状态用 `.el-tag:visible` 文案匹配 `已回签/待回签/待签章`。
