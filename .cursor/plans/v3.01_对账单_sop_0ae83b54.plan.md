# v3.01 对账单 SOP 实施计划

依据：[project-docs/prd/AutoTask v3.01 业务需求-天地伟业对账单SOP.md](project-docs/prd/AutoTask%20v3.01%20业务需求-天地伟业对账单SOP.md)。v3.0 金额校验、待生成草稿、取消仅本地、不扫 SRM **一律不改**。不 git commit（除非用户另说）。

**Goal:** 客服在填单页和详情页看到同一条六步进度；列表按落库阶段筛选；详情以阶段为主（徽章、卡点、阶段按钮、子任务树、阶段历史）。

**Architecture:** ①② 只存在于 Client 填单页本地状态，SDMS 失败仍不落库。③ 起继续用现有 `process_instances.stage`。列表/详情 API 在账单上 **附带** 实例的 `stage` / `status` / `lastError*` / `stageHistory`，Tab 改为按 `stage` 筛，不再按 `checkStatus`。Client 抽共用六步进度条，详情信息架构对齐 [app/src/features/processes/process-detail.tsx](app/src/features/processes/process-detail.tsx)。

**Tech stack:** FastAPI + SQLAlchemy；React + TanStack Query/Router。无新 RPA、无 Alembic。

## Task 2: Client SOP 模型 + 共用进度条

**Files:** `statement.ts` 类型；`statement-model.ts`；新建 `statement-sop-progress.tsx`。

六步常量（前两步仅前端 id）：

- `STMT_CREATING` 待创建
- `STMT_SDMS_CHECK` SDMS对账单核准
- `STMT_GENERATING` 待生成
- `STMT_PENDING_INVOICE` 待上传发票
- `STMT_PENDING_REVIEW` 提交审核
- `STMT_SUBMITTED` 已完成

进度条行为对齐客户订单 `StageProgress`：已走打勾、当前高亮、未到灰显。填单页传入 `currentStep=STMT_CREATING|STMT_SDMS_CHECK`；详情用实例 `stage` 映射下标（`STMT_CANCELLED` 不进主条，旁路徽章「已作废」）。列表 Tab：`all` / 上述 ③～⑥ / `STMT_CANCELLED`。阶段按钮：待生成→重新生成；待上传发票→扫描发票信息；提交审核→提交审核。

## Task 3: 填单页带六步进度

**Files:** [app/src/features/statements/statement-generate.tsx](app/src/features/statements/statement-generate.tsx)

- 打开页：`sopStep = STMT_CREATING`，顶部渲染共用进度条。
- 点「生成对账单」：先把 `sopStep` 设为 `STMT_SDMS_CHECK`，再调现有 `generate`。
- 失败（找不到 SDMS / 金额不一致）：**不跳转**，进度停在核准步，继续用现有 `mismatch` 区块展示原因。
- 成功：仍 `navigate` 到 `/process-instances/statements/$billId`（已有）。

查询收货逻辑不动，仍算「待创建」工作。
