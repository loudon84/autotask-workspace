# v5.2 调度中心（Binding 任务）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把扫单/回签从全局两个 cron 改成「一条 Binding 一行调度任务」：保存 Binding 时插入，调度中心只改 cron/开关并看任务日志。

**Architecture:** `scheduler_jobs.binding_id` 唯一。`config.schedule` 只在该 Binding 还没有调度行时写入默认值。运行时一个 `JobScheduler` 循环加载启用行，到点按 Binding 模板调用现有 `create_scan_task` 或带门户过滤的 `run_sign_poll_once`。Client 管理中心提供列表/详情，去掉设置页全局卡片。

**Tech Stack:** FastAPI + SQLAlchemy async、现有 `cron_schedule.py`、Alembic（文件可写，**未授权不执行 DDL**）、React + TanStack Router/Query、Vitest/pytest。

**Spec:** `project-docs/prd/AutoTask v5.2 调度中心.md`

```python
async def sync_scheduler_job_from_binding(db, *, binding, portal, config: dict) -> SchedulerJob | None:
    decl = parse_schedule(config)
    existing = await get_job_by_binding_id(db, binding.id)
    if existing is not None:
        return existing  # JSON 再怎么改都不覆盖
    if decl is None:
        return None
    job = SchedulerJob(
        binding_id=binding.id,
        portal_account_id=portal.id,
        name=build_job_name(portal.portal_name, decl.process_name, decl.action_name),
        cron=decl.cron,
        enabled=decl.enabled,
    )
    db.add(job)
    await db.flush()
    return job
```

Binding 停用：`existing.enabled = False`（即使 JSON 仍写 enabled true）。
