# 2026-09-20 工作日志

## 桌面端在线安装链路诊断（app/）

用户要求"看看桌面端在线安装有没有问题"。定位到 `app/` 项目下的更新链路。

### 链路拓扑
- **打包**：`forge.config.ts` 用自定义 `MakerNsisInstallDir`（在 `forge/maker-nsis-install-dir.ts`），内部调 `electron-builder` 的 `buildForge({ win: ['nsis'] })`，生成 NSIS 安装包 + `latest.yml` + `*.blockmap`，产物在 `out-pkg/make/nsis/x64/`
- **NSIS 脚本**：`installer/install-dir.nsh` 强制安装到 `D:\Programs\SMC\AutoTask`（perMachine + allowToChangeInstallationDirectory），并在 customInit 里通过 explorer 间接拉起以脱离 AutoTask 进程作业对象
- **烧入更新地址**：`MakerNsisInstallDir` 写 `resources/app-update.yml`，由 `process.env.AUTOTASK_UPDATE_URL` 覆盖，默认 `https://release.superic.com/autotask/stable/`
- **客户端拉取**：`src/main/app-updater.ts` 用 `electron-updater` 的 `generic` provider 拉 `latest.yml`，**只在 win32 + 包装态启用**（不支持 macOS/Linux）
- **更新落地**：`pending-nsis-setup.ts` 把下载的 setup.exe 从 `LocalAppData\AutoTask-updater\pending` 拷到 `D:\Programs\SMC` 根目录（绕过杀毒），再以 `--updated --force-run` 启动 NSIS（不静默、不选目录）

### 发版流程
1. `npm run make` 出 NSIS 产物
2. `scripts/build-release.ps1` 校验 sha512 → 暂存 `release/autotask/<version>/`
3. 同事 scp 到 `release.superic.com:/data/smc-release/autotask/staging/<stagingId>/`
4. `promote-autotask-release.sh` 移入 releases 并切 stable 软链
5. `scripts/publish-release.ps1`（已说明日常不用）curl 校验线上 latest.yml

### 发现的问题（已交付给用户，按严重度分级）
- **P0**：`forge.config.ts` 的 `@electron-forge/publisher-github` publisher 是死代码且仓库指向模板 `LuanRoger/electron-shadcn`；macOS 完全无更新；`stageSetupUnderSmc` 无 UAC 提权 fallback；`app-updater.ts` install 流程里 `pendingPath` 是死代码
- **P1**：`release/autotask/` 跳过 `0.1.15`；out-pkg 里 builder-debug.yml 没 gitignore；NSIS preInit 强制注册表 InstallLocation 与 allowToChangeInstallationDirectory 冲突；`main.ts` 用 `nodeIntegration: true`；`build-release.ps1` 的 `$updateUrl` dead variable；发布链路无 CI 无审计
- **P2**：CHECK_INTERVAL/FIRST_CHECK_DELAY 硬编码；`AutoTask\updates` 权限过宽；没启用 electron-updater 的 `verifyUpdateCodeSignature`

### 经验
- 这个项目（AutoTask Studio）走的是非典型自建服务器 + Forge + electron-builder 混搭的更新方案，**electron-updater 的 generator provider 必须配合 MakerNsisInstallDir 才能产出 latest.yml**
- 以后接手时优先看 `forge.config.ts`、`forge/maker-nsis-install-dir.ts`、`src/main/app-updater.ts`、`scripts/build-release.ps1` 这四个文件
- 写注册表 InstallLocation 的 `preInit` 宏是关键防呆：即使用户在 NSIS 改了目录，注册表仍然指向 `D:\Programs\SMC\AutoTask`（这点和 `allowToChangeInstallationDirectory` 是冲突的，需要用户决策）
