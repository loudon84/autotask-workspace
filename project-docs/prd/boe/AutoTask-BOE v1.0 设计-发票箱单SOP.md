## 0. 一句话

每天 7 点 **租户级** 调一次交货计划接口（接口已滤好当天+订单完成，无入参、无鉴权），用返回的子代码落到对应门户实例，**先落头再拉 WMS**。第一次 RPA 按 PO+料号补行；保存草稿独立节点；提交只打 `reviewBaseline` 的 diff。一期不传附件、AutoTask 不处理邮箱验证码（客服每天在 SRM 人工登录 AA/AD 各一次即可）。

## 1. 已定操作流程（v2.2 显示名）

```text
07:00 匹配交货计划（租户级作业，不按门户循环）
  POST 交货计划接口（无入参；当天+订单完成已在接口侧滤好）
  → 每条返回用 party_site_number 找到分类 BOE 的门户
  → 创建流程实例（头：发票号、工厂、开票日期、ETD、委托到货）
  → 停在「读 WMS 装箱单」。失败则没有单据，可重扫；成功后这条单不再匹配交货计划

读 WMS 装箱单（独立任务，参数=交货计划单号）
  → 总体积、行（PO+料号、开票数、净重、地区编号）
  → 一期不拉、不传附件（箱单/发票/双签 PO 后置）
  → 失败只重试本任务，不删单、不重跑匹配交货计划

第一次 RPA：RPA 补全项目信息行
  → 导航点进新建页，按 PO+料号查采购凭证
  → 回写行项目、剩余开票数、物料描述等
  → 搜不到 / 不唯一：失败，停本阶段，可重试补全（不重读 WMS）
  → 成功：Client 已有完整行，进入「保存 SRM 草稿单」
     （本 Run 可以不点 SRM 保存；页关掉后靠 Client 数据重建）

保存 SRM 草稿单（独立节点 / 独立 Run）
  → 按 Client 当前单据重建表单、点保存（一期不传附件）
  → 失败：把当前页字段回写 Client，停本阶段
  → 客服改 Client 后再点保存（只重试保存，不重补全、不重读 WMS）
  → 成功：回写流水号；写入校验基线 JSON；进入「客服核验」

客服核验
  → 对照基线改头/行（一期不要求附件/双签 PO）
  → 点提交；数量未对齐则硬拦，不发 RPA

提交 SRM 单据 = 变更单
  → 打开已有 SRM 草稿（流水号）
  → diff(基线 JSON, 当前 Client) 只改有差异的字段
  → 点提交成正式单
```

v2.0 曾把「补全」和「保存草稿」焊在一次 Run。v2.1 拆开，因为保存失败时必须留下 Client 上的页面数据给人改，并且 WMS / 补全 / 保存要能各自重试。

补全和保存都会再走一遍「新建+采购凭证弹窗」。这是为了节点隔离。Cookie 按 SRM 账号共享；一期不在 AutoTask 里处理邮箱码。保存那次查询只为把行挂上 SRM 表单，勾选依据已是 Client 上的 PO+料号（以及补全回写的行项目）。

## 2. 和天地伟业差在哪（仍成立）

天地伟业每步在 SRM 已有持久状态。BOE 新建页在点保存前仍是内存态。

现在有了 **SRM 草稿** 和 **Client 分步落库** 之后：

| 阶段 | 落点 | 失败怎么重试 |
| --- | --- | --- |
| 匹配交货计划 | Client 实例（仅头） | 未建单才重扫；已建单不删 |
| 读 WMS 装箱单 | Client 行/体积 | **只重试读 WMS** |
| RPA 补全项目信息行 | Client 行上 SRM 字段 | **只重试第一次 RPA**（PO+料号搜不到也停这） |
| 保存 SRM 草稿单 | SRM 草稿流水号 + 页面回写 Client | **只重试保存**；先把当前页写入 Client |
| 客服核验 | Client 相对基线的修改 | 不跑 RPA |
| 提交 SRM 单据 | SRM 正式单 | 变更单 Run：只打 diff |

登录 Cookie 按 **SRM 账号**（`V1002012AA` / `V1002012AD`）共享，不按门户。邮箱验证码一期不进 AutoTask，见 §7。

## 3. 匹配交货计划与读 WMS 装箱单（每天 7:00，两个任务）

条件「预计交货日期 = 当天 且 WMS 出库状态 = 订单完成」**由交货计划接口自己滤好**，Task 不传条件、不在本地再筛一遍。

**和天地伟业扫单的差别（2026-09-03 定稿）：** 天地伟业是按门户循环去 SRM 扫。京东方「匹配交货计划」是 **租户级定时器**，只调一次 SDMS/交货计划接口，**作业本身不绑门户、不登录 SRM**。返回里已经有子代码、交易主体、BOE 工厂，所以 AutoTask 建单时已经知道门户是谁。人手在 SRM 里要先选工厂才知道客户——那是 SRM 操作路径，不是 AutoTask 路径。开关与 cron 在 **调度中心** 维护（`autotask_settings` 热加载），不要挂 Binding、不要改 `.env` 重启。默认 `0 7 * * *`、默认关。

v2.1 拆开：

1. **匹配交货计划成功即建单**（实例已在，头已填）。幂等键 `门户（客户子代码）+ 交货计划单号`：已有未作废实例则跳过。找不到对应子代码门户则记失败/提醒，不建单。
2. **读 WMS 装箱单** 是该实例上的下一任务。接口报错 → 停在「读 WMS 装箱单」，只重试本任务，**不**再调交货计划、**不**再建一条。

### 3.1 交货计划接口 → 头

测试：`POST http://api.qywx.smart-core.com.cn/aiats/ebs_sjh_header_boe`，无 body。鉴权：与现有 SMC 接口相同，**平台无认证**。正式基址进 Task `.env`，不进 Flow。

返回字段：`doc_no`、`party_site_number`、`org_code`、`boe_factory`、`deliver_date`、`deliver_qty`。

| Client / SRM 头字段 | 取值 |
| --- | --- |
| 启用 AI 识别 | 固定否（Client 只读展示；RPA 写否） |
| 供应商发票号 | `doc_no`（交货计划单号） |
| BOE 工厂 | `boe_factory`（接口原样写入，不做工厂码白名单） |
| 客户名称 | 门户行已有，只读带出 |
| 客户子代码 | 门户行已有，只读带出（与 `party_site_number` 对齐） |
| 交易主体 | 门户行已有，只读带出 |
| 开票日期 | `deliver_date` 的日期部分 |
| ETD | 开票日期 + **匹配交货计划当时的当前时间** |
| 委托到货日期 | 开票日期 **+ 5 个自然日** |
| 总体积 | 不在本接口，见 WMS 行 `cubic` 之和 |
| 单位（体积） | **写死「立方米」**，只展示、无控件 |

`party_site_number` 用来选 **已建好的叶子门户**（一条门户 = 一个子代码，分类 `BOE`）。`org_code` 应对 芯智国际 / OU `101`（对不上记提醒，不默默改门户）。`boe_factory` 是头字段：交货计划必须带工厂编号，Task **原样写入、不按工厂码跳过或改写**。工厂名称由 SRM 按编号带出，不是再建一套门户。

### 3.2 WMS 接口（参数：交货计划单号）

测试：`http://api.qywx.smart-core.com.cn/test_demo/boe`，参数 `doc_no`。鉴权同样无认证。正式基址进 Task `.env`。`data` 是行数组（不是带 `list`/`totalVol` 的头对象）。

| 字段 | 含义 |
| --- | --- |
| `cuspo` | 客户采购订单号 → Client `poNum` |
| `cusitem` | 客户物料代码 → Client `itemNum` |
| `qty` | 本次开票数量 → Client `deliveryQty` |
| `netweight` | 净重 |
| `cubic` | **行体积**；头表总体积 = 各行 `cubic` 之和 |
| `coo` | **我方地区编号**（如 `TAIWAN,CHINA`），不是 SRM 文案 |

采购凭证查询用 **`cuspo` + `cusitem`**（落到 Client 后是 `poNum` + `itemNum`），不再只用订单号、也不依赖客服填「行项目」（行项目由 SRM 回写）。

**数量校验（2026-09-03 定稿）：** `sum(qty)`（Client `deliveryQty`）与交货计划 `deliver_qty` 不一致时，实例上 **展示报错/提醒**（读 WMS、补全、保存草稿全程可见）。匹配、读 WMS、保存草稿都是系统作业，**不因此失败、不拦住保存**。客服核验后点提交才 **硬拦**：数量未对齐则不发提交 RPA，人改行或头后再提。

### 3.3 地区配置表（Client 维护）

WMS 编号与 SRM 下拉文案没有现成映射。要一张配置：`地区编号 → SRM 显示名`（例 `TAIWAN,CHINA` → `中国台湾`）。RPA 按显示名点选项。缺映射则该行标红，校验阶段人工选。

表结构可先设计，**未授权不建库、不迁库**。

### 3.4 附件（一期不做）

箱单/发票 WMS 地址、双签 PO、提单 **全部后置**。读 WMS 只落行和体积；保存草稿与提交都不传附件；客服核验不拦「附件未齐」。规则（命名、每 PO 一份双签）仍以业务需求为准，下期再接。

### 3.5 Client 头表只显示关键字段（2026-09-03）

样例表单是整张 SRM 页，**Client 不照抄**。基本信息只出现下面这些：

| 字段 | Client | 核验可否改 |
| --- | --- | --- |
| 启用 AI 识别 | 展示「否」 | 否 |
| 供应商发票号 | 交货计划 | 可 |
| BOE 工厂 | 交货计划编号 | 可 |
| 客户名称 | 门户 | 否（改门户） |
| 客户子代码 | 门户 | 否（改门户） |
| 交易主体 | 门户 | 否（改门户） |
| 开票日期 | 交货计划 | 可 |
| ETD | 匹配当时算出 | 可 |
| 委托到货日期 | 开票日期 + 5 自然日 | 可 |
| 总体积 | WMS 行 `cubic` 之和 | 可 |
| 单位（体积） | 固定「立方米」 | 否 |

国贸条款、交货地、毛重、明细单号、海关编号、是否一次性供应商、供应商编码等 **Client 不展示**。保存草稿 RPA 只填上表对应的 SRM 控件，其余 SRM 头字段保持空/默认。流水号、SRM 状态走进度条/只读区，不塞进这张头表。

## 4. SOP 节点（客服看见的）

```text
匹配交货计划 → 读 WMS 装箱单 → RPA 补全项目信息行 → 保存 SRM 草稿单 → 客服核验 → 提交 SRM 单据 → 已完成
```

| # | 状态码（内部） | 显示文案（客服） | 谁干活 | 失败重试 |
| --- | --- | --- | --- | --- |
| ① | `BOE_PACK_SCAN_PLAN` | 匹配交货计划 | 7:00 / 手动匹配 | 未建单才重扫 |
| ② | `BOE_PACK_FETCH_WMS` | 读 WMS 装箱单 | WMS 行/体积 | **只重试读 WMS** |
| ③ | `BOE_PACK_ENRICH` | RPA 补全项目信息行 | 第一次 RPA | **只重试补全**（PO+料号搜不到也停这） |
| ④ | `BOE_PACK_SAVE_DRAFT` | 保存 SRM 草稿单 | 保存草稿 RPA | **只重试保存**；失败先把页面回写 Client |
| ⑤ | `BOE_PACK_REVIEW` | 客服核验 | 人改单 | 不跑 RPA；进入时写基线 JSON；数量不一致硬拦提交 |
| ⑥ | `BOE_PACK_SUBMITTING` | 提交 SRM 单据 | 变更单 RPA | 打开已有草稿，只打 diff |
| ⑦ | `BOE_PACK_SUBMITTED` | 已完成 | — | — |
| 旁路 | `BOE_PACK_CANCELLED` | 已作废 | 仅本地 | — |

显示名在进度条、Tab、徽章上必须一致；状态码层稳定，客服文案调整不影响接口。列表主路径从「读 WMS 装箱单」起可见（匹配交货计划成功即有单）。失败/作废沿用天地伟业旁路 + 各节点「重试」按钮。

## 5. 三次 RPA

导航约定不变：登录 → dashboard（不要存 ticket）→ **点击**送货管理 → 发票箱单。禁止 `goto` 新建/详情 URL。附件下期用 `set_input_files`，不用 pyautogui；一期不传附件。

三次 RPA 的门户行仍是实例上的子代码门户，但 **浏览器会话按 SRM 用户名共享**：`V1002012AA` 下三条门户共用一份 Cookie，不必为每个子代码各登一次。全量九家只需两个账号。

### 5.1 RPA 补全项目信息行 `srm_boe_pack_enrich`

第一次 RPA。目的是把采购凭证上的字段写回 **Client**，不要求本 Run 点 SRM 保存。

```text
登录 → 点新建
  → 对每一行：弹窗填 cuspo + cusitem（Client `poNum`/`itemNum`）→ 搜索
  → 0 行 / 多行无法唯一：本行失败，整单停在「RPA 补全项目信息行」，可重试
  → 唯一：勾选，回写行项目、剩余开票数、物料描述、工厂等
  → 闸门：开票数 ≤ 剩余开票数（可先记警告）；行工厂 vs 头工厂
```

### 5.2 保存 SRM 草稿单 `srm_boe_pack_save_draft`

独立节点。按 **Client 当前单据** 重建并点保存。

```text
登录 → 点新建（或列表已有同发票号草稿则打开改，见 §8）
  → 填头、按 PO+料号（及已回写的行项目）挂行、填开票数/净重/地区
  → 一期不上传附件
  → 点「保存」（数量不一致只在实例上显示，不拦本次保存）
  → 成功：流水号回写；生成校验基线 JSON（见 §5.4）；进入客服核验
  → 失败：把当前页头/行/附件状态回写 Client，停在本阶段
      客服改 Client 后只再点「保存 SRM 草稿单」
```

### 5.3 提交 SRM 单据 `srm_boe_pack_submit`

第二次（提交）RPA。**不是**从头录一遍，是打开已有 SRM 草稿做变更。Client 在发 Run 前校验 `sum(本次开票数) == 交货计划合计`；对不上则停在核验、不创建提交任务。

```text
登录 → 从列表用流水号打开草稿
  → diff(reviewBaseline, 当前 Client)
  → 只改有差异的头字段、行字段；增删行按 diff
  → 一期不传附件
  → 点「提交」
```

无差异：只点提交。

### 5.4 校验基线 JSON

进入「客服核验」时（保存草稿 **成功** 的那一刻）冻结一份 `reviewBaseline`。客服之后的编辑都相对这份 diff。基线只在再次成功保存草稿时重拍（核验阶段退回重保存）。

建议形状（实现前可微调，字段名以 Task schema 为准）：

```json
{
  "capturedAt": "ISO-8601",
  "srmDraftNo": "流水号",
  "header": {
    "aiRecognize": false,
    "invoiceNo": "",
    "factory": "",
    "invoiceDate": "",
    "etd": "",
    "consignArrivalDate": "",
    "totalVol": "",
    "volUnit": "立方米"
  },
  "lines": [
    {
      "poNum": "",
      "itemNum": "",
      "lineItem": "",
      "deliveryQty": "",
      "netWeight": "",
      "regionCode": "",
      "regionSrmName": ""
    }
  ],
  "attachments": [
    { "kind": "packingList|invoice|signedPo|bl", "fileName": "", "taskFileId": "" }
  ]
}
```

不含文件二进制。门户上的客户名称/子代码/交易主体不进基线（只读带出）。提交 Flow 用 `diff(reviewBaseline, 当前 Client)` 得到要改的头字段、要改/增删的行。

| `reviewBaseline` | 保存草稿成功瞬间冻结 | 只读；提交 SRM 单据用 |

## 7. 登录：Cookie 按账号共享；验证码一期不做

九家子公司只有 **两个** SRM 账号：`V1002012AA`（三家北京）、`V1002012AD`（其余六家）。同一账号进同一个 `https://supply.boe.com/`，可以操作该账号下全部子代码单据。**不是**每个子代码各登一次，不存在「三条门户互踢」。

推论：

- 叶子门户仍按子代码建（v5.5），密码可以相同。
- Engine `storage_state` / Cookie **按 SRM 用户名**缓存，不按 `portal_account_id`。
- 调度并行补全/保存时，同一账号的 Run 应串行共用会话，避免抢同一浏览器态。

**邮箱验证码一期不进 AutoTask。** 客服每天直接在 SRM 把 AA、AD 各登录一次（不走本系统）；当天之后 RPA 走用户+密码或 Cookie，后台通常不再要码。读邮件取码放到基础功能完成之后。Flow 一期不要 `WAITING_HUMAN` 等邮箱码。

Cookie 缓存仍用来少走登录页。换电脑、新开 Playwright 仍可能要走登录页，但不在 AutoTask 里拦验证码。

## 9. 状态机

```text
[*] → 匹配交货计划 : 作业触发或手动匹配
匹配交货计划 → 读 WMS 装箱单 : 建单成功（仅头）
匹配交货计划 → 匹配交货计划 : 未建单，可重扫
读 WMS 装箱单 → RPA 补全项目信息行 : WMS 行/体积已落
读 WMS 装箱单 → 读 WMS 装箱单 : WMS 失败，只重试读数
RPA 补全项目信息行 → 保存 SRM 草稿单 : 第一次 RPA 回写成功
RPA 补全项目信息行 → RPA 补全项目信息行 : PO+料号搜不到或不唯一，只重试补全
保存 SRM 草稿单 → 客服核验 : 保存成功（流水号 + reviewBaseline）
保存 SRM 草稿单 → 保存 SRM 草稿单 : 保存失败，页面回写 Client，只重试保存
客服核验 → 保存 SRM 草稿单 : 客服退回重保存（可选；会重拍基线）
客服核验 → 提交 SRM 单据 : 点提交且数量已对齐
客服核验 → 客服核验 : 数量不一致，硬拦不发提交 RPA
提交 SRM 单据 → 已完成 : 变更单提交成功
提交 SRM 单据 → 客服核验 : 提交失败，可改后再提
任意未完成 → 已作废 : 仅本地
已完成 → [*]
```

## 10. 架构

```text
调度 07:00 → 匹配交货计划作业（租户级，交货计划 HTTP，无浏览器、不循环门户）
    → 按 party_site_number 落到 BOE 子代码门户 → 实例（仅头）
    → 读 WMS 装箱单任务（行/体积；一期无附件）
    → 补全 Flow srm_boe_pack_enrich → Client 行上 SRM 字段
    → 保存草稿 Flow srm_boe_pack_save_draft → 流水号 + reviewBaseline
    → 客服核验（相对基线改单；数量未对齐则硬拦提交）
    → 提交 Flow srm_boe_pack_submit → diff 后点提交 → 正式单
```

`process_code`：`srm_boe_invoice_packing`。门户仍一条 = 一个子 code。交货计划/WMS 基址走 Task `.env`，不进 Flow。RPA Cookie 按 SRM 用户名，不按门户 id。
