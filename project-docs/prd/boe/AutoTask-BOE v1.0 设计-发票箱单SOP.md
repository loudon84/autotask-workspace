## 0. 一句话

每天 7 点 **租户级** 调一次交货计划接口（接口已滤好当天+订单完成，无入参、无鉴权），用返回的子代码落到对应门户实例，**先落头再拉 WMS**。第一次 RPA 按 PO+料号补行；保存草稿独立节点；提交只打 `reviewBaseline` 的 diff。同一点还有独立定时器 `boe.srm_login`：自动登录 AA/AD 并读邮件打验证码（见 [邮件读取](./AutoTask-BOE%20邮件读取.md)），白天任务不再依赖客服先去 SRM 登录。

## 1. 已定操作流程（v2.2 显示名）

```text
07:00 匹配交货计划（租户级作业，不按门户循环）
  POST 交货计划接口（无入参；当天+订单完成已在接口侧滤好）
  → 每条返回用 party_site_number 找到分类 BOE 的门户
  → 创建流程实例（头：发票号、工厂、开票日期、ETD、委托到货）
  → 停在「读 WMS 装箱单」。失败则没有单据，可重扫；成功后这条单不再匹配交货计划

读 WMS 装箱单（独立任务，参数=交货计划单号）
  → 总体积、行（PO+料号、开票数、净重、地区编号）
  → 一期不拉、不传附件（箱单/发票/双签 PO 后置）
  → 失败只重试本任务，不删单、不重跑匹配交货计划

第一次 RPA：RPA 补全项目信息行
  → 导航点进新建页，按 PO+料号查采购凭证
  → 回写行项目、剩余开票数、物料描述等
  → 搜不到 / 不唯一：失败，停本阶段，可重试补全（不重读 WMS）
  → 成功：Client 已有完整行，进入「保存 SRM 草稿单」
     （本 Run 可以不点 SRM 保存；页关掉后靠 Client 数据重建）

保存 SRM 草稿单（独立节点 / 独立 Run）
  → 按 Client 当前单据重建表单、点保存（一期不传附件）
  → 失败：把当前页字段回写 Client，停本阶段
  → 客服改 Client 后再点保存（只重试保存，不重补全、不重读 WMS）
  → 成功：回写流水号；写入校验基线 JSON；进入「客服核验」

客服核验
  → 对照基线改头/行（一期不要求附件/双签 PO）
  → 点提交；数量未对齐则硬拦，不发 RPA

提交 SRM 单据 = 变更单
  → 打开已有 SRM 草稿（流水号）
  → diff(基线 JSON, 当前 Client) 只改有差异的字段
  → 点提交成正式单
```

v2.0 曾把「补全」和「保存草稿」焊在一次 Run。v2.1 拆开，因为保存失败时必须留下 Client 上的页面数据给人改，并且 WMS / 补全 / 保存要能各自重试。

补全和保存都会再走一遍「新建+采购凭证弹窗」。这是为了节点隔离。Cookie 按 SRM 账号共享；邮箱验证码由 Task 读邮件 + 晨间登录定时器处理，见 [邮件读取](./AutoTask-BOE%20邮件读取.md)。保存那次查询只为把行挂上 SRM 表单，勾选依据已是 Client 上的 PO+料号（以及补全回写的行项目）。

## 2. 和天地伟业差在哪（仍成立）

天地伟业每步在 SRM 已有持久状态。BOE 新建页在点保存前仍是内存态。

现在有了 **SRM 草稿** 和 **Client 分步落库** 之后：

| 阶段 | 落点 | 失败怎么重试 |
| --- | --- | --- |
| 匹配交货计划 | Client 实例（仅头） | 未建单才重扫；已建单不删 |
| 读 WMS 装箱单 | Client 行/体积 | **只重试读 WMS** |
| RPA 补全项目信息行 | Client 行上 SRM 字段 | **只重试第一次 RPA**（PO+料号搜不到也停这） |
| 保存 SRM 草稿单 | SRM 草稿流水号 + 页面回写 Client | **只重试保存**；先把当前页写入 Client |
| 客服核验 | Client 相对基线的修改 | 不跑 RPA |
| 提交 SRM 单据 | SRM 正式单 | 变更单 Run：只打 diff |

登录 Cookie 按 **SRM 账号**（`V1002012AA` / `V1002012AD`）共享，不按门户。邮箱验证码见 §7 与 [邮件读取](./AutoTask-BOE%20邮件读取.md)。

## 3. 匹配交货计划与读 WMS 装箱单（每天 7:00，两个任务）

条件「预计交货日期 = 当天 且 WMS 出库状态 = 订单完成」**由交货计划接口自己滤好**，Task 不传条件、不在本地再筛一遍。

**和天地伟业扫单的差别（2026-09-03 定稿）：** 天地伟业是按门户循环去 SRM 扫。京东方「匹配交货计划」是 **租户级定时器**，只调一次 SDMS/交货计划接口，**作业本身不绑门户、不登录 SRM**。返回里已经有子代码、交易主体、BOE 工厂，所以 AutoTask 建单时已经知道门户是谁。人手在 SRM 里要先选工厂才知道客户——那是 SRM 操作路径，不是 AutoTask 路径。开关与 cron 在 **调度中心** 维护（`autotask_settings` 热加载），不要挂 Binding、不要改 `.env` 重启。默认 `0 7 * * *`、默认关。

v2.1 拆开：

1. **匹配交货计划成功即建单**（实例已在，头已填）。幂等键 `门户（客户子代码）+ 交货计划单号`，**只约束未作废实例**：已有未作废则跳过。作废后不占键，定时器/立即匹配同一入口，下次会新建。找不到对应子代码门户则记失败/提醒，不建单。
2. **读 WMS 装箱单** 是该实例上的下一任务。接口报错 → 停在「读 WMS 装箱单」，只重试本任务，**不**再调交货计划、**不**再建一条。

### 3.1 交货计划接口 → 头

测试：`POST http://api.qywx.smart-core.com.cn/aiats/ebs_sjh_header_boe`，无 body。鉴权：与现有 SMC 接口相同，**平台无认证**。正式基址进 Task `.env`，不进 Flow。

返回字段：`doc_no`、`header_id`、`party_site_number`、`org_code`、`boe_factory`、`deliver_date`、`deliver_qty`。`header_id` 写入实例 `summary.headerId`，**不进可改头表**；Client 用它打开 SDMS 交货计划**查看**页（`method=viewDpInfo&fdId=`），不打开编辑。已有实例再匹配时若还没有 `headerId` 会补上。

| Client / SRM 头字段 | 取值 |
| --- | --- |
| 启用 AI 识别 | 固定否（Client 只读展示；RPA 写否） |
| 供应商发票号 | `doc_no`（交货计划单号） |
| BOE 工厂 | `boe_factory`（接口原样写入，不做工厂码白名单） |
| 客户名称 | 门户行已有，只读带出 |
| 客户子代码 | 门户行已有，只读带出（与 `party_site_number` 对齐） |
| 交易主体 | 门户行已有，只读带出 |
| 开票日期 | `deliver_date` 的日期部分 |
| ETD | 开票日期 + **匹配交货计划当时的当前时间** |
| 委托到货日期 | 开票日期 **+ 5 个自然日** |
| 总体积 | 不在本接口，见 WMS 行 `cubic` 之和 |
| 单位（体积） | **写死「立方米」**，只展示、无控件 |

`party_site_number` 用来选 **已建好的叶子门户**（一条门户 = 一个子代码，分类 `BOE`）。`org_code` 应对 芯智国际 / OU `101`（对不上记提醒，不默默改门户）。`boe_factory` 是头字段：交货计划必须带工厂编号，Task **原样写入、不按工厂码跳过或改写**。工厂名称由 SRM 按编号带出，不是再建一套门户。

### 3.2 WMS 接口（参数：交货计划单号）

正式：`http://api.qywx.smart-core.com.cn/aiats/wms_sjh_pl_boe`，参数 `erpno`（交货计划单号）。鉴权无认证。基址进 Task `.env` 的 `SMC_API_BASE_URL`；路径写死在 `boe_smc_client`（测/正式相同，只换域名）。`data` 是平铺行数组（`cuspo`/`cusitem`/`qty`/`netweight`/`cubic`/`coo`），头表总体积=各行 `cubic` 之和。`doc_no` 现返回空数组，不要用。

| 字段 | 含义 |
| --- | --- |
| `cuspo` | 客户采购订单号 → Client `poNum` |
| `cusitem` | 客户物料代码 → Client `itemNum` |
| `qty` | 本次开票数量 → Client `deliveryQty` |
| `netweight` | 净重 |
| `cubic` | **行体积**；头表总体积 = 各行 `cubic` 之和 |
| `coo` | **我方地区编号**（如 `TAIWAN,CHINA`），不是 SRM 文案 |

采购凭证查询用 **`cuspo` + `cusitem`**（落到 Client 后是 `poNum` + `itemNum`），不再只用订单号、也不依赖客服填「行项目」（行项目由 SRM 回写）。

**数量校验（2026-09-03 定稿）：** `sum(qty)`（Client `deliveryQty`）与交货计划 `deliver_qty` 不一致时，实例上 **展示报错/提醒**（读 WMS、补全、保存草稿全程可见）。匹配、读 WMS、保存草稿都是系统作业，**不因此失败、不拦住保存**。客服核验后点提交才 **硬拦**：数量未对齐则不发提交 RPA，人改行或头后再提。

### 3.3 地区配置表（Client 维护）

**地区对照（2026-09-10）：** WMS `coo` 必须在地区对照表里能解析出 SRM 显示名。找不到（编号空、表里没有、或显示名为空）则 **停在「读 WMS 装箱单」并报错**，不派补全 RPA。客服维护对照后点重试，再读 WMS 映射成功才进入「RPA 补全项目信息行」。

表结构可先设计，**未授权不建库、不迁库**。测库已迁 `b2d4f6a81935`。

### 3.4 附件（客服核验手工上传）

保存草稿仍不传附件。客服核验页手工上传并校验：每行一个 PDF；箱单建议 `PL-{发票号}.pdf`，硬限制是文件名包含 `pl`（大小写均可）；发票=`{发票号}.pdf`；提运单文件名不限；双签 PO/协议数量=交货明细唯一 PO，文件名=`{PO}.pdf`。箱单/发票/提运单对齐 SRM 默认行（删除 disabled），核验页不提供删除；只有双签可新增或删除。本期 RPA 提交 Binding `dryRun: true`：把核验改动和附件写到 SRM 草稿并保存，不点「提交」。

### 3.5 Client 头表只显示关键字段（2026-09-03）

样例表单是整张 SRM 页，**Client 不照抄**。基本信息只出现下面这些：

| 字段 | Client | 核验可否改 |
| --- | --- | --- |
| 发票箱单流水号 | 只读区第一项；没有则空 | 否 |
| 交货计划 | 只读区：`bizKey` 可点进 SDMS 查看页 | 否 |
| 启用 AI 识别 | 展示「否」 | 否 |
| 供应商发票号 | 交货计划 | 可 |
| BOE 工厂 | 交货计划编号 | 可 |
| 客户名称 | 门户 | 否（改门户） |
| 客户子代码 | 门户 | 否（改门户） |
| 交易主体 | 门户 | 否（改门户） |
| 开票日期 | 交货计划 | 可 |
| ETD | 匹配当时算出 | 可 |
| 委托到货日期 | 开票日期 + 5 自然日 | 可 |
| 总体积 | WMS 行 `cubic` 之和 | 可 |
| 单位（体积） | 固定「立方米」 | 否 |

国贸条款、交货地、毛重、明细单号、海关编号、是否一次性供应商、供应商编码等 **Client 不展示**。保存草稿 RPA 只填上表对应的 SRM 控件，其余 SRM 头字段保持空/默认。流水号、交货计划、SRM 状态走进度条/只读区，不塞进这张可改头表：查看 SDMS 交货计划与核验编辑发票箱单分开。列表第一列也是发票箱单流水号（空也占列），第二列交货计划。

## 4. SOP 节点（客服看见的）

```text
匹配交货计划 → 读 WMS 装箱单 → RPA 补全项目信息行 → 保存 SRM 草稿单 → 客服核验 → 提交 SRM 单据 → 已完成
```

| # | 状态码（内部） | 显示文案（客服） | 谁干活 | 失败重试 |
| --- | --- | --- | --- | --- |
| ① | `BOE_PACK_SCAN_PLAN` | 匹配交货计划 | 7:00 / 手动匹配 | 未建单才重扫 |
| ② | `BOE_PACK_FETCH_WMS` | 读 WMS 装箱单 | WMS 行/体积 | **只重试读 WMS** |
| ③ | `BOE_PACK_ENRICH` | RPA 补全项目信息行 | 第一次 RPA | **只重试补全**（PO+料号搜不到也停这） |
| ④ | `BOE_PACK_SAVE_DRAFT` | 保存 SRM 草稿单 | 保存草稿 RPA | **只重试保存**；失败先把页面回写 Client |
| ⑤ | `BOE_PACK_REVIEW` | 客服核验 | 人改单 | 不跑 RPA；进入时写基线 JSON；数量不一致硬拦提交 |
| ⑥ | `BOE_PACK_SUBMITTING` | 提交 SRM 单据 | 变更单 RPA | 打开已有草稿，只打 diff |
| ⑦ | `BOE_PACK_SUBMITTED` | 已完成 | — | — |
| 旁路 | `BOE_PACK_DELETING_DRAFT` | 删除 SRM 草稿 | 作废 2.2 RPA | 有流水号时先删 SRM 草稿；失败可重试 |
| 旁路 | `BOE_PACK_CANCELLED` | 已作废 | 2.1 仅本地；2.2 删草稿成功后 | — |

显示名在进度条、Tab、徽章上必须一致；状态码层稳定，客服文案调整不影响接口。列表主路径从「读 WMS 装箱单」起可见（匹配交货计划成功即有单）。失败/作废沿用天地伟业旁路 + 各节点「重试」按钮。

## 5. 四次 RPA

导航约定不变：登录 → dashboard（不要存 ticket）→ **点击**送货管理 → 发票箱单。禁止 `goto` 新建/详情 URL。附件下期用 `set_input_files`，不用 pyautogui；一期不传附件。

三次 RPA 的门户行仍是实例上的子代码门户，但 **浏览器会话按 SRM 用户名共享**：`V1002012AA` 下三条门户共用一份 Cookie，不必为每个子代码各登一次。全量九家只需两个账号。作废 2.2 的删除草稿是第四次 RPA，同一套登录/导航。

### 5.1 RPA 补全项目信息行 `srm_boe_pack_enrich`

第一次 RPA。目的是把采购凭证上的字段写回 **Client**，不要求本 Run 点 SRM 保存。

```text
登录 → 点新建
  → 对每一行：弹窗填 cuspo + cusitem（Client `poNum`/`itemNum`）→ 搜索
  → 0 行 / 多行无法唯一：本行失败，整单停在「RPA 补全项目信息行」，可重试
  → 唯一：勾选，回写行项目、剩余开票数、物料描述、工厂等
  → 闸门：开票数 ≤ 剩余开票数（可先记警告）；行工厂 vs 头工厂
```

### 5.2 保存 SRM 草稿单 `srm_boe_pack_save_draft`

独立节点。按 **Client 当前单据** 重建并点保存。

```text
登录 → 点新建（或列表已有同发票号草稿则打开改，见 §8）
  → 填头、按 PO+料号（及已回写的行项目）挂行、填开票数/净重/地区
  → 一期不上传附件
  → 点「保存」（数量不一致只在实例上显示，不拦本次保存）
  → 成功：流水号回写；生成校验基线 JSON（见 §5.4）；进入客服核验
  → 保存接口可能不关窗、甚至不回 HTTP（库里已经有单）。RPA 先等表单流水号，没有则点「返回」再按发票号搜列表，不能只等 `.invoice-list` 自动出现
  → 失败：把当前页头/行/附件状态回写 Client，停在本阶段
      客服改 Client 后只再点「保存 SRM 草稿单」
```

### 5.3 提交 SRM 单据 `srm_boe_pack_submit`

第二次（提交）RPA。**不是**从头录一遍，是打开已有 SRM 草稿做变更。Client 在发 Run 前校验 `sum(本次开票数) == 交货计划合计`；对不上则停在核验、不创建提交任务。

```text
登录 → 列表展开 → 填发票箱单流水号 → 搜索 → 等该行出现再点流水号按钮打开草稿
  → diff(reviewBaseline, 当前 Client)
  → 只改有差异的头字段、已有行的本次开票数/净重；新增行按 diff 挂采购凭证
  → 上传核验页附件并保存
  → dryRun=true：到此结束，不点「提交」
  → dryRun=false：再点「提交」成正式单
```

无差异：dryRun 只保存；正式才点提交。

### 5.3.1 客服核验 = 变更单（2026-09-08 已定）

保存草稿成功瞬间冻结 `reviewBaseline`。核验页顶部「相对保存草稿基线的变更」就是这份 diff。点提交时 RPA 只打 diff，不重建整张单。

| 谁改 | 字段 | 提交 RPA 怎么做 |
| --- | --- | --- |
| 客服可改 | 头：发票号、工厂、开票日期、ETD、委托到货、总体积 | 打开草稿后按 diff 回填 |
| 客服可改 | 行：本次开票数、净重 | 打开草稿后等项目信息**有数据**，再按 PO+料号改 |
| 客服可改 | 新增一行（新的 PO+料号） | 采购凭证弹窗：填 PO+料号 → 搜索 → **等有数据** → 勾选挂行 |
| 客服可改 | 附件 | 前三行按 箱单/发票/提运单 **直接上传**，不新增、不换序；双签按 Client 份数点「新增」再传 |
| 只读回写 | 客户PO、客户料号、净重单位、地区编号、SRM 地区、行项目、订单数量、订单单位、剩余开票数 | 进基线、进 diff 展示；提交不重录这些列 |
| 不进基线 | 门户客户三字段、体积单位 | 只读展示 |

基线只在再次成功保存草稿时重拍。删行本期不做。`dryRun: true` 时变更落到 SRM 草稿，单据仍可继续改。

### 5.3.2 提交时怎么传附件（2026-09-08 已定）

SRM 草稿打开后附件表默认就是三行：箱单、发票、提运单，类型锁死、删除不可点。保存草稿时已经把空的双签行删掉了。

```text
箱单 → 第 1 行右侧冻结列点「上传文件」（不要点新增、不要改类型）
发票 → 第 2 行同样点「上传文件」
提运单 → 第 3 行（核验页没选文件则跳过）
每个双签 PDF → 点「新增」→ 类型选「双签PO/协议」→ 再点该行「上传文件」
→ 点保存
```

「上传文件」在 `.el-table__fixed-right` 操作列（`a.elBtnA` / `label.uploader-btn`），点开后再喂文件；不要给行内可能未绑定的隐藏 `input[type=file]` 直接 `set_input_files`。不要按类型去扫已有行再决定新增；类型下拉读不到值时会把箱单传到第四行、顺序反掉。

## 7. 登录：Cookie 按账号共享；验证码走邮件读取

九家子公司今天常见 **两个** SRM 账号：`V1002012AA`（三家北京）、`V1002012AD`（其余六家），以后门户里出现第三个登录账号也按同样规则处理。同一账号进同一个 `https://supply.boe.com/`，可以操作该账号下全部子代码单据。**不是**每个子代码各登一次，不存在「三条门户互踢」。账号个数以门户 `loginAccount` 去重为准，不要写死两个。

推论：

- 叶子门户仍按子代码建（v5.5），密码可以相同。
- Engine `storage_state` / Cookie **按 SRM 用户名**缓存，不按 `portal_account_id`。
- 调度并行补全/保存时，同一账号的 Run 应串行共用会话，避免抢同一浏览器态。

**邮箱验证码记在 SRM 后台（账号 + 自然日），不是 Cookie。** 电脑 A 打过码，电脑 B 当天再登同一账号通常不要码。AutoTask 用 Task 侧 IMAP 读信打码，不再以客服每天去 SRM 登录为主路径。

- 默认每天 7 点定时器 `boe.srm_login`：读启用中的京东方门户，按登录账号去重后串行登录（失败重试不超过 2 次）。
- 验证码收件人 = 门户 `extra.email`（分类专属 JSONB；BOE 描述符声明，天地伟业没有该字段）。
- 码 5 分钟有效。只认本账号、且是这一次点「获取验证码」之后的新信（IMAP UID 水位）；历史码不用。当天已经登过、账密后没有验证码页，则不读邮件。
- 白天补全/保存/提交若仍出现 CAS「获取验证码」，走同一套读信，不抛给人等。
- 读邮件是平台能力，验证码只是场景 1；订单邮件建销售订单后置。

细节、重试、`.env` 键、与发票箱单 Flow 的边界见 [AutoTask-BOE 邮件读取.md](./AutoTask-BOE%20邮件读取.md)。本文不记录授权码。

Cookie 缓存仍用来少走登录页。换电脑、新开 Playwright 仍可能要走登录页，但验证码由读信填写。

## 10. 架构

```text
调度 07:00 → 匹配交货计划作业（租户级，交货计划 HTTP，无浏览器、不循环门户）
    → 按 party_site_number 落到 BOE 子代码门户 → 实例（仅头）

    → 保存草稿 Flow srm_boe_pack_save_draft → 流水号 + reviewBaseline
    → 客服核验（相对基线改单；数量未对齐则硬拦提交）
    → 提交 Flow srm_boe_pack_submit → diff 后点提交 → 正式单
作废：无流水号仅本地 CANCELLED；有流水号先 Flow srm_boe_pack_delete_draft，成功后再作废
```

`process_code`：`srm_boe_invoice_packing`。门户仍一条 = 一个子 code。交货计划/WMS 基址走 Task `.env`，不进 Flow。RPA Cookie 按 SRM 用户名，不按门户 id。
