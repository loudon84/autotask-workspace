## 0. 一句话

每天 7 点扫交货计划，**先落 Client 单据再拉 WMS**（WMS 失败只重试拉数，不重扫）。第一次 RPA 按 PO+料号补行并回写；搜不到停本节点重试。保存 SRM 草稿是独立节点，失败把页面回写 Client，改完再保存。进入校验时打一份字段 JSON 基线；提交 RPA 只做 **变更单**（diff 后改 SRM 草稿再提交）。

## 1. 已定操作流程（v2.2 显示名）

```text
07:00 匹配交货计划（交货计划接口）
  预计交货日期=当天 且 WMS出库状态=订单完成
  → 创建流程实例（头：发票号、工厂、开票日期、ETD、委托到货）
  → 停在「读 WMS 装箱单」。失败则没有单据，可重扫；成功后这条单不再匹配交货计划

读 WMS 装箱单（独立任务，参数=交货计划单号）
  → 总体积、行（PO+料号、开票数、净重、地区编号）、箱单/发票文件
  → 失败只重试本任务，不删单、不重跑匹配交货计划

第一次 RPA：RPA 补全项目信息行
  → 导航点进新建页，按 PO+料号查采购凭证
  → 回写行项目、剩余开票数、物料描述等
  → 搜不到 / 不唯一：失败，停本阶段，可重试补全（不重读 WMS）
  → 成功：Client 已有完整行，进入「保存 SRM 草稿单」
     （本 Run 可以不点 SRM 保存；页关掉后靠 Client 数据重建）

保存 SRM 草稿单（独立节点 / 独立 Run）
  → 按 Client 当前单据重建表单、上传箱单发票、点保存
  → 失败：把当前页字段回写 Client，停本阶段
  → 客服改 Client 后再点保存（只重试保存，不重补全、不重读 WMS）
  → 成功：回写流水号；写入校验基线 JSON；进入「客服核验」

客服核验
  → 对照基线改头/行/附件；补双签 PO
  → 点提交

提交 SRM 单据 = 变更单
  → 打开已有 SRM 草稿（流水号）
  → diff(基线 JSON, 当前 Client) 只改有差异的字段/附件
  → 点提交成正式单
```

v2.0 曾把「补全」和「保存草稿」焊在一次 Run。v2.1 拆开，因为保存失败时必须留下 Client 上的页面数据给人改，并且 WMS / 补全 / 保存要能各自重试。

补全和保存都会再走一遍「新建+采购凭证弹窗」。这是为了节点隔离；登录 Cookie 与当天免邮箱码仍然成立。保存那次查询只为把行挂上 SRM 表单，勾选依据已是 Client 上的 PO+料号（以及补全回写的行项目）。

## 2. 和天地伟业差在哪（仍成立）

天地伟业每步在 SRM 已有持久状态。BOE 新建页在点保存前仍是内存态。

现在有了 **SRM 草稿** 和 **Client 分步落库** 之后：

| 阶段 | 落点 | 失败怎么重试 |
| --- | --- | --- |
| 匹配交货计划 | Client 实例（仅头） | 未建单才重扫；已建单不删 |
| 读 WMS 装箱单 | Client 行/体积/箱单发票 | **只重试读 WMS** |
| RPA 补全项目信息行 | Client 行上 SRM 字段 | **只重试第一次 RPA**（PO+料号搜不到也停这） |
| 保存 SRM 草稿单 | SRM 草稿流水号 + 页面回写 Client | **只重试保存**；先把当前页写入 Client |
| 客服核验 | Client 相对基线的修改 | 不跑 RPA |
| 提交 SRM 单据 | SRM 正式单 | 变更单 Run：只打 diff |

登录 Cookie、邮箱验证码规则不变，见 §7。

## 3. 匹配交货计划与读 WMS 装箱单（每天 7:00，两个任务）

条件：交货计划 **预计交货日期 = 当天**，且 **WMS 出库状态 = 订单完成**。

v2.1 拆开：

1. **匹配交货计划成功即建单**（实例已在，头已填）。幂等键 `门户（客户子代码）+ 交货计划单号`：已有未作废实例则跳过。
2. **读 WMS 装箱单** 是该实例上的下一任务。接口报错 → 停在「读 WMS 装箱单」，只重试本任务，**不**再调交货计划、**不**再建一条。

### 3.1 交货计划接口 → 头

返回：交货计划单号、客户子代码、交易主体编号、BOE 工厂编号、预计交货日期、合计交货数量。

| Client / SRM 头字段 | 取值 |
| --- | --- |
| 供应商发票号 | 交货计划单号 |
| BOE 工厂 | BOE 工厂编号 |
| 开票日期 | 预计交货日期 |
| ETD | 开票日期 + **匹配交货计划当时的当前时间** |
| 委托到货日期 | 开票日期 **+ 5 个自然日** |
| 启用 AI 识别 | 固定否（RPA 写） |
| 总体积 | 不在本接口，见 WMS `totalVol` |

客户子代码用来选门户；交易主体应对 芯智国际 / OU `101`（对不上记提醒，不默默改门户）。

### 3.2 WMS 接口（参数：交货计划单号）

| 字段 | 含义 |
| --- | --- |
| `totalVol` | 总体积 |
| `po_num` | 客户采购订单号 |
| `item_num` | 客户物料代码（SRM 物料编码） |
| `delivery_qty` | 本次开票数量 |
| `net_Weight` | 净重 |
| `region` | **我方地区编号**（如 `China_tw`），不是 SRM 文案 |

采购凭证查询用 **`po_num` + `item_num`**（订单号 + 物料编码），不再只用订单号、也不依赖客服填「行项目」（行项目由 SRM 回写）。

**数量提醒（不默认阻断扫单）：** `sum(delivery_qty)` 与交货计划「合计交货数量」不一致，实例上展示提醒，客服校验时处理。

### 3.3 地区配置表（Client 维护）

WMS 编号与 SRM 下拉文案没有现成映射。要一张配置：`地区编号 → SRM 显示名`（例 `China_tw` → `中国台湾`）。RPA 按显示名点选项。缺映射则该行标红，校验阶段人工选。

表结构可先设计，**未授权不建库、不迁库**。

### 3.4 附件

| 类型 | 来源 |
| --- | --- |
| 箱单、发票 | WMS 附件接口给文件地址；**读 WMS 装箱单时**落到 Task（对账单 v5.3 同一模型） |
| 双签 PO/协议 | **客服手工传**，有几个 PO 传几份 |
| 提单 | 无要求，可空 |

命名规则仍按需求：箱单 `PL-{发票号}`，发票为发票号本体。

## 4. SOP 节点（客服看见的）

```text
匹配交货计划 → 读 WMS 装箱单 → RPA 补全项目信息行 → 保存 SRM 草稿单 → 客服核验 → 提交 SRM 单据 → 已完成
```

| # | 状态码（内部） | 显示文案（客服） | 谁干活 | 失败重试 |
| --- | --- | --- | --- | --- |
| ① | `BOE_PACK_SCAN_PLAN` | 匹配交货计划 | 7:00 / 手动匹配 | 未建单才重扫 |
| ② | `BOE_PACK_FETCH_WMS` | 读 WMS 装箱单 | WMS + 附件接口 | **只重试读 WMS** |
| ③ | `BOE_PACK_ENRICH` | RPA 补全项目信息行 | 第一次 RPA | **只重试补全**（PO+料号搜不到也停这） |
| ④ | `BOE_PACK_SAVE_DRAFT` | 保存 SRM 草稿单 | 保存草稿 RPA | **只重试保存**；失败先把页面回写 Client |
| ⑤ | `BOE_PACK_REVIEW` | 客服核验 | 人改单、传双签 PO | 不跑 RPA；进入时写基线 JSON |
| ⑥ | `BOE_PACK_SUBMITTING` | 提交 SRM 单据 | 变更单 RPA | 打开已有草稿，只打 diff |
| ⑦ | `BOE_PACK_SUBMITTED` | 已完成 | — | — |
| 旁路 | `BOE_PACK_CANCELLED` | 已作废 | 仅本地 | — |

显示名在进度条、Tab、徽章上必须一致；状态码层稳定，客服文案调整不影响接口。列表主路径从「读 WMS 装箱单」起可见（匹配交货计划成功即有单）。失败/作废沿用天地伟业旁路 + 各节点「重试」按钮。

## 5. 三次 RPA

导航约定不变：登录 → dashboard（不要存 ticket）→ **点击**送货管理 → 发票箱单。禁止 `goto` 新建/详情 URL。附件用 `set_input_files`，不用 pyautogui。

### 5.1 RPA 补全项目信息行 `srm_boe_pack_enrich`

第一次 RPA。目的是把采购凭证上的字段写回 **Client**，不要求本 Run 点 SRM 保存。

```text
登录 → 点新建
  → 对每一行：弹窗填 po_num + item_num → 搜索
  → 0 行 / 多行无法唯一：本行失败，整单停在「RPA 补全项目信息行」，可重试
  → 唯一：勾选，回写行项目、剩余开票数、物料描述、工厂等
  → 闸门：开票数 ≤ 剩余开票数（可先记警告）；行工厂 vs 头工厂
```

### 5.2 保存 SRM 草稿单 `srm_boe_pack_save_draft`

独立节点。按 **Client 当前单据** 重建并点保存。

```text
登录 → 点新建（或列表已有同发票号草稿则打开改，见 §8）
  → 填头、按 PO+料号（及已回写的行项目）挂行、填开票数/净重/地区
  → 上传已在 Task 的箱单、发票
  → 点「保存」
  → 成功：流水号回写；生成校验基线 JSON（见 §5.4）；进入客服核验
  → 失败：把当前页头/行/附件状态回写 Client，停在本阶段
      客服改 Client 后只再点「保存 SRM 草稿单」
```

### 5.3 提交 SRM 单据 `srm_boe_pack_submit`

第二次（提交）RPA。**不是**从头录一遍，是打开已有 SRM 草稿做变更。

```text
登录 → 从列表用流水号打开草稿
  → diff(reviewBaseline, 当前 Client)
  → 只改有差异的头字段、行字段；增删行按 diff
  → 新附件（双签 PO 等）只传新增
  → 点「提交」
```

无差异且附件已齐：只点提交。

### 5.4 校验基线 JSON

进入「客服核验」时（保存草稿 **成功** 的那一刻）冻结一份 `reviewBaseline`。客服之后的编辑都相对这份 diff。基线只在再次成功保存草稿时重拍（核验阶段退回重保存）。

建议形状（实现前可微调，字段名以 Task schema 为准）：

```json
{
  "capturedAt": "ISO-8601",
  "srmDraftNo": "流水号",
  "header": {
    "invoiceNo": "",
    "factory": "",
    "invoiceDate": "",
    "etd": "",
    "consignArrivalDate": "",
    "totalVol": ""
  },
  "lines": [
    {
      "poNum": "",
      "itemNum": "",
      "lineItem": "",
      "deliveryQty": "",
      "netWeight": "",
      "regionCode": "",
      "regionSrmName": ""
    }
  ],
  "attachments": [
    { "kind": "packingList|invoice|signedPo|bl", "fileName": "", "taskFileId": "" }
  ]
}
```

不含文件二进制。提交 Flow 用 `diff(reviewBaseline, 当前 Client)` 得到要改的头字段、要改/增删的行、要新传的附件。

## 6. 字段谁说了算

| 数据 | 来源 | Client 上 |
| --- | --- | --- |
| 头：发票号、工厂、开票日期、ETD、委托到货、体积 | 交货计划 + WMS | 可改（校验阶段） |
| 行：PO、料号、开票数、净重、地区编号 | WMS | 可改；地区经配置表转 SRM 名 |
| 行：行项目、剩余开票数、物料描述等 | SRM 弹窗 | 只读回写 |
| 箱单 / 发票文件 | WMS 地址 | Task 文件 |
| 双签 PO | 客服 | 校验阶段必齐再提交 |
| 流水号、SRM 状态 | 保存草稿 / 提交回读 | 只读 |
| `reviewBaseline` | 保存草稿成功瞬间冻结 | 只读；提交 SRM 单据用 |

## 7. 登录：Cookie ≠ 邮箱验证码

| | 天地伟业图片码 | BOE 邮箱码 |
| --- | --- | --- |
| 记在哪 | Engine `storage_state`（Cookie） | **SRM 后台，账号 + 自然日** |
| 换电脑 | 通常再打码 | **当天不用** |
| 新开 Playwright | 无 Cookie 要再登录 | 要走登录页，但当天多半不再出邮箱码 |

Cookie 缓存 BOE 同样用来少走登录页。邮箱码是否出现看后台，不看 Cookie。

## 9. 状态机

```text
[*] → 匹配交货计划 : 作业触发或手动匹配
匹配交货计划 → 读 WMS 装箱单 : 建单成功（仅头）
匹配交货计划 → 匹配交货计划 : 未建单，可重扫
读 WMS 装箱单 → RPA 补全项目信息行 : WMS 行/体积/箱单发票已落
读 WMS 装箱单 → 读 WMS 装箱单 : WMS 失败，只重试读数
RPA 补全项目信息行 → 保存 SRM 草稿单 : 第一次 RPA 回写成功
RPA 补全项目信息行 → RPA 补全项目信息行 : PO+料号搜不到或不唯一，只重试补全
保存 SRM 草稿单 → 客服核验 : 保存成功（流水号 + reviewBaseline）
保存 SRM 草稿单 → 保存 SRM 草稿单 : 保存失败，页面回写 Client，只重试保存
客服核验 → 保存 SRM 草稿单 : 客服退回重保存（可选；会重拍基线）
客服核验 → 提交 SRM 单据 : 点提交（双签 PO 已齐）
提交 SRM 单据 → 已完成 : 变更单提交成功
提交 SRM 单据 → 客服核验 : 提交失败，可改后再提
任意未完成 → 已作废 : 仅本地
已完成 → [*]
```

## 10. 架构

```text
调度 07:00 → 匹配交货计划作业（交货计划，无浏览器）→ 实例（仅头）
    → 读 WMS 装箱单任务（行/体积/箱单发票）
    → 补全 Flow srm_boe_pack_enrich → Client 行上 SRM 字段
    → 保存草稿 Flow srm_boe_pack_save_draft → 流水号 + reviewBaseline
    → 客服核验（相对基线改单）+ 双签 PO
    → 提交 Flow srm_boe_pack_submit → diff 后点提交 → 正式单
```

`process_code`：`srm_boe_invoice_packing`。门户仍一条 = 一个子 code。地区配置、接口基址走 Task `.env` / 配置表，不进 Flow 源码。
