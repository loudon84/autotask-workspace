## 0. 一句话

AutoTask 在 Task 服务里做 **通用邮件读取**（先接阿里企业邮箱 IMAP），用 **场景** 消化邮件，不把读信写成「只给验证码用」的一次性脚本。场景 1 是京东方每天首次登录的邮箱验证码：默认 **07:00** 读本租户京东方门户，按 **登录账号去重** 后各登录一次（失败重试不超过 2 次），白天发票箱单 RPA 再走用户+密码即可。

---

## 1. 要解决什么

京东方 SRM **每个自然日每个账号第一次登录**必须邮箱验证码。码记在 **SRM 后台（账号 + 当天）**，不是浏览器 Cookie：电脑 A 打过码，电脑 B 当天再登同一账号通常也不要码。

现在客服每天自己去 SRM 把 AA、AD 各登一次，效果差：人忘了、人晚了、白天第一笔补全就卡在 `BOE_OTP_REQUIRED`。

目标：

1. **上班前打完码。** 默认每天 7 点（中国时区）自动登录「门户里实际有多少个不重复 SRM 账号」。今天两个，以后三个也一样，不写死 AA/AD。
2. **任务执行变简单。** 验证码已经在 SRM 记过，白天补全/保存/提交只走账号密码或已有会话。
3. **读邮件可复用。** 后面会用邮件里的订单信息建销售订单，读信层不能写死验证码。

不在本设计：客服在 Client 里手工翻邮件；用邮件替代门户密码；把授权码写进 Flow / Binding / 文档。

## 2. 口径（2026-09-08）

1. **读邮件是平台能力，归 Task。** IMAP 连接、文件夹、原始邮件、按场景解析，都在 `service/`。Engine / Flow 不直连邮箱、不内嵌授权码。
2. **场景是插件，不是 if 验证码。** 先落地场景 `boe_srm_otp`。预留 `sales_order_from_mail`（本期不实现）。新增场景只加处理器，不改 IMAP 连接器。
3. **IMAP 账号和业务收件人不是一回事。** 探测脚本登录的是系统邮箱（`.env`）。验证码信的 **To** 来自 **京东方门户 `extra.email`**（每个门户对应一个客服）。登录目标不写 `.env`、不写死 AA/AD：到点扫启用中的 BOE 门户，按 `loginAccount` 去重。不要给门户加 `email` 列。
4. **触发是独立定时器** `boe.srm_login`，默认 `0 7 * * *`，默认关，调度中心维护。与 `boe.pack_match` 分开：匹配交货计划是 HTTP、不登 SRM；晨间登录才是 RPA。
5. **每个账号每次触发，登录失败后最多再试 2 次**（含首次最多 3 次点「获取验证码」/提交验证码）。超过则停该账号、记失败，避免锁号。另一账号继续。
6. **密钥只进 Task `.env`。** 探测脚本禁止写死授权码。日志、`timer_runs`、RunEvent 不写验证码正文、不写授权码。
7. **SOP §7「一期不做验证码」作废。** 客服不再作为每天登录 AA/AD 的主路径；漏跑定时器时，白天 RPA 登录仍应走同一套读邮件打码，而不是再抛 `BOE_OTP_REQUIRED` 等人。
8. **验证码只认「这一次点获取验证码」。** 码 5 分钟有效。按本账号 `extra.email` 匹配 `To`，并用点之前的 IMAP UID 水位丢掉历史信。禁止拿文件夹里「最新一封」或另一账号的码。账密之后若没有验证码页，当天已免验证码，**不要读邮件**。

`service/scripts/probe_ali_mail.py` 已用 IMAP SSL 读到文件夹里的信，并能从正文抽出 6 位码。实现时沿用这些事实，不要另起一套协议。

| 项 | 值（非密钥） |

## 5. 从门户读登录账号和邮箱（不要写死）

京东方是 **一个分类、多条叶子门户**。每条门户已经有登录账号（`loginAccount`，例如今天的 `V1002012AA` / `V1002012AD`），并且 **每个门户对应一个客服**。验证码寄到那个客服的邮箱，所以邮箱必须挂在门户上，而不是写进 `.env`。

| 谁 | 存在哪 | 说明 |
| --- | --- | --- |
| 系统 IMAP（读信） | Task `.env` | 一个邮箱，用来拉文件夹 |
| SRM 登录账号 | 门户 `loginAccount` | 九家子公司可以共用两个账号；以后变成三个就再加一条门户 |
| 验证码收件人 | 门户 `extra.email` | **分类描述符声明、动态表单渲染**；天地伟业描述符为空，没有该字段 |

到点登录前：

1. 列出本租户 **启用中、分类 = BOE** 的门户。
2. 按 `loginAccount`（去空白）**去重**：同一账号只登录一次（北京三家都填 AA，只打一次码）。
3. 该账号的收件人 = 这些门户上的 `extra.email`。同一账号若填了两个不同邮箱，视为配置错误，该账号本轮失败，不要猜。
4. 该账号所有门户都没填邮箱：该账号失败并提示补门户邮箱。
5. 今天结果是 2 个账号，明天多一个门户用了新登录账号，就会自动变成 3 次登录，不用改代码、不用改 `.env`。

读信时用该账号门户上的邮箱去匹配 `To`（及验证码文件夹）。去重后的账号 **串行** 点「获取验证码」。只用「这一次点击」之后、且 `To` 对得上、且未超过 5 分钟的信；历史验证码不用。账密后没有验证码页则不读邮件。

现网示例（只作说明，实现时仍读门户行）：AA 门户填 `xiongjing@smart-core.com.cn`，AD 门户填 `csr02@smartcorelink.com`。客服在门户编辑里维护，不写配置文件。

## 6. 分层：连接器 / 消息 / 场景

```text
.env  IMAP 账号
        │
        ▼
   MailConnector（IMAP：连接、选文件夹、拉原始信）
        │
        ▼
   MailMessage（from / to / subject / date / text / folder / uid）
        │
        ├── 场景 boe_srm_otp     → 6 位码（现）
        └── 场景 sales_order_*   → 以后建销售订单（现只留接口）
```

### 6.1 连接器

- 只负责连通和取信。不知道验证码、不知道 SRM。
- 入参：host/port/user/auth/folder/readonly。
- 出参：`MailMessage` 列表或按 uid 取一封。
- 中文文件夹名走 modified UTF-7（探测脚本已有编解码）。
- 以后可以加第二套连接器（另一 IMAP、或 Graph），场景代码不动。

### 6.2 消息

统一字段即可，本期不必落库：

- `uid`、`folder`、`from`、`to`、`subject`、`sent_at`、`text_body`
- 场景需要 HTML 时再加 `html_body`；OTP 用纯文本足够。

订单场景再考虑：去重表、附件、已处理标记。OTP 场景 **实时拉、用完即弃**，不把码写入数据库。

### 6.3 场景接口（预留订单）

每个场景实现同一形状，例如：`match(message) -> bool` 以及 `parse(message) -> typed payload`。

| 场景代码 | 匹配（示意） | 产出 | 本期 |
| --- | --- | --- | --- |
| `boe_srm_otp` | 文件夹 = 验证码文件夹，且 To 等于这次登录门户上的邮箱 | `{ srmUsername, code, mailUid, sentAt }` | 做 |
| `sales_order_from_mail` | 以后：主题/发件人/专表文件夹 | 销售订单草稿字段 | 只留空接口或 `NotImplemented` |

禁止在连接器里写 `if folder == 验证码`。文件夹名属于场景配置。

## 7. 场景 1：BOE SRM 验证码登录

### 7.1 谁触发

新定时器，登记在 `timer_catalog`，与现网定时器同一套调度中心：

| 项 | 值 |
| --- | --- |
| `target` | `boe.srm_login` |
| 名称 | 京东方-SRM晨间登录 |
| 默认 cron | `0 7 * * *`（中国业务日） |
| 默认 enabled | `false`（运维打开） |
| 登记 | 已写入 `timer_catalog` + `main` register；**重启 Task 4520** 后调度中心出现。到点目前只核对门户账号/邮箱，CAS 打码 RPA 尚未接入 |
| 立即执行 | 已有 `POST /timers/{id}/run`，不受 cron/开关限制，便于联调 |

`boe.pack_match` 仍是 07:00 HTTP 匹配，**不登 SRM**，可以和晨间登录同一分钟；白天真正用 Cookie/免验证码的是补全/保存/提交 RPA。若担心 Worker 抢会话，晨间登录先跑完去重后的账号再让人点补全即可（匹配建单本身不登录）。

### 7.2 到点做什么

对本租户启用中的 BOE 门户按 §5 去重后的每个 SRM 账号 **串行**：

1. 用该账号下任意一条门户取密码和 Binding / 薄登录 Flow。
2. 派一次 **只登录** 的 RPA（不要走发票箱单补全）。
3. Engine `login_boe_srm`：账号密码 → 若当天已免验证码（没有「获取验证码」）则结束、**不读邮件**；若 CAS 出现邮箱验证码区则按 §7.3 打码。
4. 成功则该账号当天 SRM 侧已记码；Cookie/`storage_state` 仍按用户名缓存（少走登录页，但免验证码靠的是 SRM 后台不是 Cookie）。
5. 一个账号失败不影响另一个；整次定时结果写入 `timer_runs`（摘要允许写「AA 成功 / AD 失败」，禁止写验证码）。

### 7.3 CAS 页面步骤（影刀）

验证码在 `supply.boe.com/cas/login` 的 `#twoFactorAuth`，不是进系统之后的弹窗。现网 `otp_dialog = text=获取验证码` 只用来 **侦测** 要不要码。

**今天这种已经登过的情况：** 输入账号密码后没有验证码区 → 直接成功。文件夹里昨天/早上的码一律不用。

需要打码时按影刀补选择器，并且 **只接受这一次点击产生的信**：

1. 门户首页点「供应商登录」。
2. 填 `#username` / `#password`，勾隐私政策，点登录。
3. 没有「获取验证码」：结束。有则认证方式选 **邮箱**（`#emailAuth` / 文案「邮箱」）。
4. **先**读取验证码文件夹当前最大 IMAP UID，记为 `watermark`；再点 **获取验证码**（`#getCodeBtn`），记下本地时间 `t0`。不要先点再去翻旧信。
5. Task 轮询该文件夹，同时满足才用：
   - `To` = 本账号门户 `extra.email`（大小写不敏感；另一账号的信直接丢掉）
   - `uid > watermark`（点获取验证码之前就在的信 = 历史，不用，哪怕还在 5 分钟内）
   - 邮件时间 ≥ `t0`（时钟偏差最多 15 秒）
   - 距今不超过 **5 分钟**（过期码不用）
   - 多封都合格时取 UID 最大的一封（刚触发的那封）
6. 抽出 6 位码，填 `#verificationCode`。
7. 点登录提交，等到首页/导航元素（现有登录成功判定不变）。

去重后的账号 **串行** 点「获取验证码」，避免 AA、AD 两封新信时间挤在一起。即使挤在一起，也靠 `To` 隔离，不能串码。

匹配实现：`service/app/domain/boe_srm_otp.py`（`pick_fresh_otp`）。禁止「按文件夹最新一封抽码」。

### 7.4 重试与锁号

| 情况 | 行为 |
| --- | --- |
| 门户密码错、找不到表单 | 该账号立即失败，**不再点获取验证码** |
| IMAP 连不上 / 授权码错 | 整次定时失败；**不要**为了重试去点获取验证码 |
| 点了获取验证码但超时无新信 | 算 1 次失败；同一账号可再点获取验证码，**再试最多 2 次** |
| 填了码仍停在验证码页 | 同上，计入重试 |
| 该账号已用满「1 次 + 2 次重试」 | 停止该账号，告警；不要第四次点获取验证码 |
| 另一账号尚未做 | 继续做 |

「错误重试不能超过 2 次」约束的是 **SRM 要码动作**，不是 IMAP 握手。IMAP 短暂断线可自行重连几次，不计入这 2 次。

轮询建议：点获取验证码后每 3～5 秒拉一次文件夹，总等待不超过约 90 秒再算本次失败。具体秒数实现时写死可配置即可。

### 7.5 白天任务

`login_boe_srm` 与晨间登录共用同一套打码。7 点没跑、或换日第一笔 RPA，仍自动读邮件，而不是 `BOE_OTP_REQUIRED` 等人。

白天重试上限同样适用，避免补全失败循环把号打封。建议按 **账号 + 自然日** 记住已经点过多少次获取验证码（进程内或短 TTL 即可），不要每个 Flow 包各计一套。

### 7.6 薄登录 Flow

定时器不要复用 `rpa_flow_srm_boe_pack_enrich`（会进发票箱单）。单独一个小包，例如 `rpa_flow_srm_boe_login`：只调 `login_boe_srm` 成功即结束。

Binding：去重后每个 SRM 账号至少能从一条启用中的京东方门户拿到密码（复用任一已绑发票箱单门户的凭据即可）。账号集合以门户行为准，不要假设永远只有 AA/AD。

## 8. 配置（`.env`，无密钥）

写在 Task `service/.env`。`service/.env.example` 只给空键。不要进 Binding JSON、不要进 Client、不要进本文填写。

| 键 | 含义 |
| --- | --- |
| `ALI_MAIL_HOST` | 默认 `imap.qiye.aliyun.com` |
| `ALI_MAIL_PORT` | 默认 `993` |
| `ALI_MAIL_USER` | 系统邮箱完整地址 |
| `ALI_MAIL_AUTH` | 客户端授权码 |
| `ALI_MAIL_FOLDER` | 默认 `BOE-SRM一站式平台-验证码` |
| `ALI_MAIL_READONLY` | 默认 `true` |

不要把 SRM 账号或客服邮箱写进 `.env`。那两样在京东方门户上维护。

定时器开关与 cron **仍以调度中心为准**（与 `boe.pack_match` 相同），不要再做一套 `BOE_SRM_LOGIN_JOB_HOUR` 重启才生效的循环。

## 9. 安全

- 授权码、验证码、邮件正文不得出现在 PRD、SOP、`PROJECT_CONTROL`、`lat.md`、日志默认级别、截图 OCR 回传。
- 失败截图尽量避开已填验证码的输入框；不能避开则证据保留策略与现网一致，但 RunEvent 摘要只写「已提交验证码」不写数字。
- 探测脚本从仓库去掉写死的授权码；若该文件曾提交或外传，**轮换**阿里邮箱客户端授权码。
- 只读 IMAP 为默认，避免标记已读影响人工排障；订单场景若需要「已处理」再单独设计，不在 OTP 场景改邮件状态。
