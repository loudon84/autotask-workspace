### 问题清单

```
1、和天地伟业不一样的是，我天地伟业天然可以切分多个节点。每个节点流程都可以直接去处理rpa. 
现在的新建发货箱单：主表、项目信息行表、附件行 
都是一个完整单据。也就是都是一次性填写完成保存后提交。 
那么怎么去设计SOP节点呢？我填写一个字段就是RPA还是主表填写完操作RPA还是说整个单据操作完成，再去操作RPA。
```

  思路：
    天地伟业的每个节点对应 SRM 里一个持久化状态页：下载 XLSX、上传附件、签章、提交审核——每一步做完，SRM 里就落一个稳定状态，下一个节点从那个状态接着走。所以 1 阶段 ≈ 1 Run 是天然的。

```
BOE 的发票箱单完全不同：主表 + 行表 + 附件是同一个瞬态表单会话，只有点了「保存」才落草稿。这带来三条硬约束：

约束	推论
SRM 表单是内存态，单字段/主表无处可存	「填一个字段就 RPA」「填完主表 RPA」没有落点——RPA 每次都得从登录开始重建整个表单
每次 Run = 登录 + 邮箱验证码（WAITING_HUMAN 人工介入）	Run 次数 = 验证码次数。切 4 次 Run = 客服每张单输 4 次验证码，不可接受
行数据的来源是 SRM 本身（采购凭证查询弹框）	人要填「本次开票数/净重」，必须先有人把行数据查回来——查询必须在人工填行之前发生
```

设计结论（2026-09-01）：客服在 Client 填齐并保存（落我们库），再触发 **一次提交 Run**。查询采购凭证发生在这次 Run 的采购订单弹窗里。

两套记住不要混：天地伟业图片验证码靠 Engine Cookie 缓存；BOE 邮箱验证码记在 **SRM 后台（账号+当天）**，换电脑也免，不是 Cookie。Cookie 缓存 BOE 仍可用（少走登录页）。不能跨 Run 带走的是未保存新建表单。Client 只存指令；提交时对页校验剩余开票数。详见设计 §1.1、§6.4。

这样rpa才可以简化而不是重头操作一遍。
你可以理解，第二次rpa就是一个变更单。
