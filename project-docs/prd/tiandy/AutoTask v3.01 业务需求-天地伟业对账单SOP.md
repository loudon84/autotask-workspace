## 0. 版本关系

```text
v3.0   天地伟业对账单业务定稿（生成/发票/提交/待生成草稿）
  └─ v3.01  本文：对账单查看与操作对齐客户订单 SOP（阶段、步骤、卡点）
```

v3.0 已解决「做什么」：生成对账单、上传发票、提交审核、待生成草稿、取消仅本地。  
v3.01 解决「怎么看」：客服打开对账单时，应像客户订单一样知道 **整条 SOP 走到哪一步、下一步点什么、卡在哪**。

实施完成后：将本文「变更后行为」视为对账单前台现行说明；v3.0 业务规则（SDMS 校验、匹配键、不扫 SRM、流程终点等）继续有效。

## 1. 问题（v3.0 落地后）

客户订单（`/processes`）已经是 SOP：

- 列表 Tab = **阶段**（建单中 / 待填写交期 / 待签章 / …）
- 列区分 **阶段** 与 **运行状态**
- 详情顶部：**阶段主徽章 + 运行状态辅徽章**
- **流程进度条**展示整条步骤
- 主按钮由当前阶段决定
- 失败/待人工用 **卡点条**，不把整单误显示成「进行中且无下一步」
- 子任务按节点树状展示，可进 Run

对账单（`/process-instances/statements`）目前更像一张 **SRM 对账单台账**：

- 列表 Tab = **对账状态**（待生成 / 未对账 / 已作废 / 已对账），把 SOP 中间步骤压成「未对账」
- 详情以头表字段 + 发票路径框为主，**没有进度条、没有阶段徽章、没有阶段历史**
- 生成/填单页也看不到整条 SOP，客服不知道填单属于第几步
- 子任务是扁平列表，不像客户订单按节点聚合

后台其实已有 `process_instances.stage`（`STMT_GENERATING` 等），前台没用它当主叙事。

## 3. 设计原则（对齐客户订单）

| 原则 | 说明 |
| --- | --- |
| 用户只看到一条 SOP | 侧栏仍是「流程实例 → 对账单」；点进去是「天地伟业对账单处理流程」 |
| 一条进度走到底 | **填单页和详情页画同一套六步**，只是当前步不同 |
| SOP 节点驱动 | 落库之后每张对账单 = 一条 `process_instances`（`srm_tiandi_statement`） |
| 待人工为主 | 待生成之后多数时间待客服点阶段按钮；按钮背后才是 RPA |
| 阶段名必须统一 | 同一阶段在进度条、列表 Tab、详情徽章上 **中文名完全一致** |
| 前两步不落库 | 「待创建」「SDMS 对账单核准」只存在于填单页；SDMS 失败仍不写库（继承 v3.0） |

## 4. SOP 节点清单（客服可见步骤）

主路径 **六步**（进度条全程画这些；已作废不进主条，单独展示）：

```text
待创建 → SDMS对账单核准 → 待生成 → 待上传发票 → 提交审核 → 已完成
```

| 节点 | 阶段标识 | 显示文案 | 发生在哪 | 客服含义 | 主按钮 |
| --- | --- | --- | --- | --- | --- |
| ① | `STMT_CREATING`（仅前端） | 待创建 | **填单页** | 选门户、选入库确认日期、搜索收货、按行勾选 | 搜索 / **生成对账单** |
| ② | `STMT_SDMS_CHECK`（仅前端） | SDMS对账单核准 | **填单页** | 已点生成，正在（或已经）用勾选汇总与 SDMS `check_amount` 核对 | 校验中无按钮；失败留在本页看原因，改数后重新点生成 |
| ③ | `STMT_GENERATING` | 待生成 | 流程实例详情 | SDMS 已通过，本地草稿已落库；RPA 正在或需重新在 SRM 生成 | 失败时 **重新生成**；进行中等 RPA |
| ④ | `STMT_PENDING_INVOICE` | 待上传发票 | 详情 | SRM 已生成；客服在本页选择发票（不跑 RPA） | **提交审核**（须已选文件） |
| ⑤ | `STMT_PENDING_REVIEW` | 提交审核 | 详情 | 历史遗留阶段；与④同一工作区（重新选文件后提交） | **提交审核** |
| ⑥ | `STMT_SUBMITTED` | 已完成 | 详情 | 我方流程结束（已对账 / 发票审批中） | 无（可查看证据） |
| 旁路 | `STMT_CANCELLED` | 已作废 | 详情/列表 | 本地取消，只读 | 无 |

> 「待生成」仍是本系统草稿，SRM 无此状态。  
> 「待创建」「SDMS 对账单核准」**不是**列表里的流程实例：还没有 `process_instances` / `statement_bills`。

### 4.1 填单页两步（①②）怎么切

都在同一张「生成客户对账单」填单页，**不跳转**：

```text
打开填单页
  → 当前步 = 待创建
  → 选门户 + 日期 + 搜索收货 + 勾选行（查询 RPA 属于本步工作，不是单独 SOP 步）
  → 点「生成对账单」
      → 当前步 = SDMS对账单核准（同页展示校验中）
      → 找不到单 / 金额不一致：留在填单页，进度条停在「SDMS对账单核准」，展示双方金额
      → 金额一致：落库待生成草稿，离开填单页，进入该实例详情（当前步 = 待生成）
```

SDMS 失败 **不落库**（v3.0 决策 #17 / #23 仍有效）。

### 4.2 阶段与账单字段对照（③ 起才有行）

| SOP 阶段 | `check_status` | `invoice_status` |
| --- | --- | --- |
| 待创建 / SDMS对账单核准 | （无账单行） | — |
| 待生成 | `DRAFT` | 未上传 |
| 待上传发票 | `UNCHECKED` | 未上传 |
| 提交审核 | `UNCHECKED` | 未上传（历史遗留可能为已上传，仍须重新选文件提交） |
| 已完成 | `CHECKED` | 审批中 |
| 已作废 | `VOID` | — |

列表 **禁止** 用「未对账」当 Tab。「未对账」只作详情业务字段。

### 4.3 各节点完成条件

| 节点 | 进入 | 完成并进入下一步 |
| --- | --- | --- |
| 待创建 | 打开填单页 | 用户点「生成对账单」（勾选至少一行） |
| SDMS对账单核准 | 已点生成 | SDMS 金额一致 |
| 待生成 | 校验通过并落草稿 | 生成 RPA **SUCCESS** 且回写对账日期/金额 |
| 待上传发票 | 生成成功 | 客服已选发票并点提交审核，且 **一次 RPA SUCCESS**（扫描回写发票号/总额并提交） |
| 提交审核 | （历史遗留） | 同上；新单据成功后直接进入已完成，不再在此等待 |
| 已完成 | 提交成功 | 终点；不跟踪 SRM 后续审批 |

失败：

- ①②：留在填单页；② 展示 SDMS 原因。
- ③④⑤：停留当前阶段，详情卡点条；点该阶段主按钮重试。生成失败 **不** 把实例打成 `FAILED`。

## 5. 客服视角

### 5.1 列表页

标题：**「对账单流程实例」**。头部 **「生成客户对账单」** 进入填单页（SOP ①）。

**Tab（只筛已落库实例）：**

全部 / 待生成 / 待上传发票 / 提交审核 / 已完成 / 已作废

不提供「待创建」「SDMS对账单核准」Tab——这两步没有实例。

**列：**

| 列 | 来源 | 说明 |
| --- | --- | --- |
| 客户 | 门户 `portal_name` | 显式展示，对齐客户订单 |
| 对账日期 | `statement_bills.check_date` | 业务键之一 |
| 对账金额 | `statement_bills.check_amount` | 业务键之一 |
| 阶段 | `process_instances.stage` | ③～⑥ / 已作废 的中文名 |
| 运行状态 | `process_instances.status` | 进行中 / 已完成 / 已取消 |
| 更新时间 | 实例或账单 `updated_at` | 北京时间 |
| 操作 | 由阶段决定 | 「详情」始终有；另给阶段按钮（重新生成 / 提交审核）。待生成、待上传发票、提交审核可「取消对账」 |

默认 Tab：**全部**。

### 5.2 详情页（③ 起）

进度条仍画 **全部六步**（①② 已打勾），当前步从 待生成 起：

```text
┌─ 标题：对账单 {对账日期} / {对账金额}     [阶段按钮…] [返回列表]
├─ 徽章：阶段：待上传发票    运行状态：进行中
├─ 卡点条（若有）
├─ 流程进度：待创建 ✅ → SDMS核准 ✅ → 待生成 ✅ → 待上传发票 当前 → 提交审核 → 已完成
├─ 业务信息：对账日期/金额、对账状态、发票状态、发票号、发票总额
├─ 本阶段工作区：③ 重新生成；④ 扫描发票回写到页面核验；⑤ 提交审核（再扫一次，必须与页面一致）
├─ 子任务树：生成 / 提交审核（历史上传发票若有记录仍展示；查询收货若有记录，挂在①下折叠）
└─ 阶段历史：从待生成起的落库阶段变更（①②无库记录，不编造历史行）
```

主按钮只由 **当前落库阶段** 决定。卡点条对齐 v2.02 O3。

### 5.3 填单页（①②）

同一页必须带 **六步进度条**，当前步只可能是「待创建」或「SDMS对账单核准」。

| 当前步 | 页上内容 |
| --- | --- |
| 待创建 | 门户、入库确认起止、搜索、收货勾选表、勾选汇总、「生成对账单」 |
| SDMS对账单核准 | 不换页；按钮进入校验中；失败用原位置展示 SDMS 原因与双方金额，进度条停在本步 |

校验通过后跳到该草稿 **详情**（当前步待生成），不要回到空列表。

## 6. 与现有实现的关系

| 层 | v3.01 要求 |
| --- | --- |
| `statement_bills` | 保留；仍从待生成才插入 |
| `process_instances` | 待生成才创建；列表/详情 SOP 主对象 |

## 7. 明确不做

- 不改 v3.0 业务边界（不跟踪 SRM 审批通过/驳回，不扫历史未对账单，取消不对 SRM 操作）。
- 不做跨客户通用对账单模板引擎。
- 不为「待创建 / SDMS对账单核准」创建流程实例（避免 SDMS 失败也落库）。
- 不把「未对账」「待人工核对」当作 SOP 阶段名；提交前那一步的显示名是 **提交审核**。
- 查询收货不是第六步之外的另一步，它包含在 **待创建**。
- 发票选择使用系统文件对话框（最多 10 个；png / jpg / jpeg / pdf / ofd；单个 ≤20MB）。

## 8. 验收标准

1. 填单页打开时进度条六步齐全，当前为 **待创建**；点生成后当前变为 **SDMS对账单核准**（同页）。
2. SDMS 失败：仍在填单页、进度停在核准步、不落库。
3. SDMS 通过：跳转详情，进度条 ①② 已勾，当前为 **待生成**。
4. 列表 Tab 为：全部 / 待生成 / 待上传发票 / 提交审核 / 已完成 / 已作废；没有「未对账」。
5. 详情具备：阶段 + 运行状态、六步进度条、卡点条、按节点子任务、落库阶段历史。
6. 选择发票不发起 RPA；点「提交审核」后一次成功，阶段为 **已完成**，发票号/总额已回写。
7. 提交失败仍停在待上传发票（未对账/未上传），可重新选文件再提交。
8. 同一阶段中文名在填单页进度条、列表、详情完全一致。
9. v3.0 金额校验、待生成草稿、取消仅本地等规则回归通过。
