## 0. 先看这张总表

三种「能不能做」：

| 标记 | 含义 |
| --- | --- |
| **现在可演练** | Client 选「天地伟业-国际-正式演练」就能点；RPA 会进正式 SRM。写 SRM 的步骤只定位按钮，不真点。 |
| **要人核对后点** | RPA 不替你做业务判断。必须看页面数字/发票后，再点 Client 按钮。 |
| **等单据 / 等上线** | 正式站现在没有这类单，或红线不允许真写。Flow 已按上线路径写好，缺的是单据或关掉 `dryRun`。 |

### 0.1 客户订单

```text
扫待签章 → 建 SDMS 销售订单 → 填交期并保存 → 签章 → 回签轮询 → 下载签章合同到 SDMS
```

| 节点 | 现在 | 谁点 Client | 正式 SRM 会不会被改 |
| --- | --- | --- | --- |
| 扫待签章 | **现在可演练** | 点扫单 | 否（只查询导出） |
| 建 SDMS | **现在可演练** | 扫单成功后自动建；失败可重试 | 否（只下载订单）；**测试 SDMS 会真建单** |
| 填交期并保存 | **等单据** | 有待签章单才有「填写交货日期」 | 演练不点保存；上线才保存 |
| 签章 | **等单据** | 有待签章且交期齐才有「去签章」 | 演练不点签章；上线才签 |
| 回签轮询 | **现在可演练**（已回签样例） | 一般自动；可点立即轮询 | 否（只读状态） |
| 下合同 | **现在可演练**（已回签样例） | 已回签后自动或点手动下载 | 否（只下载「查看签章」）；**测试 SDMS 会真传附件** |

### 0.2 对账单

```text
填单搜收货 → SDMS 金额核准 → 生成对账单 → 扫描发票 → 核对后提交审核 → 已完成
```

| 节点 | 现在 | 谁点 Client | 正式 SRM 会不会被改 |
| --- | --- | --- | --- |
| 搜收货勾选 | **现在可演练** | 填单页搜、勾选 | 否 |
| SDMS 核准 | **现在可演练** | 点「生成对账单」先走校验 | 否；校验失败不落库 |
| 生成对账单 | **现在可演练**（只验按钮） | 校验通过后等 RPA | **不点生成**。本地可有待生成草稿，门户**不会**多一张未对账 |
| 扫描发票 | **现在可演练** | 详情选文件，点「扫描发票」 | **会扫描**（含弹窗确定）。不点提交审核 |
| 核对发票 | **要人核对后点** | 看详情发票号/总额，对得上再点「提交审核」 | 无 |
| 提交审核 | **现在可演练**（不真提交） | 核对后点「提交审核」 | 再扫一次并比对；**不点门户提交**。本地仍未对账 |
| 真提交 / 已完成 | **等上线** | 同一按钮 | Binding 去掉 `dryRun` 后才会点门户「提交审核」，本地才变已对账 |

## 2. 演练怎么配、上线怎么配

同一份正式 Flow。**不要**再做「演练包 / 上线包」。上线改 Binding，不换产品线。

### 2.1 共用规则

| 键 | 演练 | 上线 |
| --- | --- | --- |
| `portalUrl` | `https://supplier.tiandy.com` | 不变 |
| 只读包（扫单、查收货、回签、下合同、扫描发票） | **不设** `dryRun` | 不设 |
| 会改 SRM 的包（填交期、签章、生成对账单、提交审核） | `dryRun: true` | **删除该键或改为 `false`**，须单独授权 |
| 建 SDMS | **不设** `dryRun`（否则会拦住我们自己的 SDMS POST） | 不设 |
| 扫单 `searches` | 先待签章，再加样例单号 | **只留待签章一条** |
| `treatAsPending` | 只允许出现在演练 Binding | **禁止** |
| SDMS / ERP 基址 | Task `.env` 指向测试 | 改 `.env` 指向生产后重启唯一 Task 4520 |

成功标准：

| | 演练成功 | 上线成功 |
| --- | --- | --- |
| 看什么 | 登录到了、按钮找到了、该点的点了、不该点的没点；Artifact 有截图 | SRM 状态按 SOP 变了 |
| `committed` | 写步骤为 `false` | `true` 或缺省 |
| 本地阶段 | **不往前**（生成仍待生成；提交仍待上传发票/未对账） | 按 v2.02 / v3.0 推进 |
| Client | 可出现琥珀色「演练未提交」 | 无此徽章；对账单提交后为已完成 |

### 2.2 当前正式演练 Binding（2026-08-21）

演示门户包版本不要改到下表。

| SOP 节点 | workflow | 正式包 | dryRun | 上线时改什么 |
| --- | --- | --- | --- | --- |
| 扫待签章 | `srm_scan_pending_orders` | **1.1.3** | 无 | Binding `searches` 只留 `{ "replyStatus": "待签章" }` |
| 建 SDMS | `srm_prepare_erp_order` | **1.2.15** | 无 | 不改闸；SDMS 地址改 `.env` |
| 填交期 | `srm_update_delivery_dates` | 未按待签章真跑 | 要 `true` | 等正式站出现待签章后再验收保存 |
| 签章 | `srm_sign_order` | 未按待签章真跑 | 要 `true` | 同上 |
| 回签探测 | `srm_check_reply_status` | **1.1.4** | 无 | 不改闸 |

扫单演练 Binding（**已写入**门户「天地伟业-国际-正式演练」，打开 Binding 编辑即可看到）：

```json
{
  "portalUrl": "https://supplier.tiandy.com",
  "searches": [
    { "replyStatus": "待签章" },
    { "poNo": "POJS2607170008", "treatAsPending": true }
```

换演练单号：改第二条 `poNo`，保存后再扫。上线只留第一条。`treatAsPending` 不得进生产。

## 3. 客户订单 SOP

客服可见主路径：

```text
建单中 → 待填写交期 → 待签章 → 待回签 → 已回签 → 已完成
```

正式站样例 `POJS2607170008` **已经是已回签**，没有交期框、保存、签章。演练用它走「扫入 → 建 SDMS → 回签探测 → 下合同」，**跳过填交期/签章**，不编造成功。

### 3.1 扫待签章

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | Client 选正式演练门户，点扫单 | 同样点扫单 |
| RPA | 回复状态=待签章 → 查询 → 导出 Excel。没有行则再按样例单号导出，把该单**当成**待签章扫入（不改 SRM） | 只查待签章。没有行就是空列表成功，不再扫样例单 |
| 现在 | **可演练** | 等生产 Binding 收掉第二条 `searches` |

### 3.2 建 SDMS 销售订单

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 通常自动；失败在详情重试 | 同 |
| RPA | 订单列表点可见「详情」→ 下载订单 → **真写测试 SDMS** | 同；SDMS 换成生产地址 |
| 现在 | **可演练** | 改 `.env` 前不要对着生产 SDMS 点 |

### 3.3 填交期并保存

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 详情点填写交货日期 | 同 |
| RPA | 能填则填框，定位「保存」后 **不点** | 同一包，关掉 `dryRun` 才保存 |
| 现在 | **等单据**。需要正式站出现真实「待签章」且详情有交期输入 | 有单且授权关闸后才能验收真保存 |

没有保存按钮时记「选择器未覆盖」，**不许编造成功**。不要用已回签单假装填交期成功。正式门户**没有**填交期 Binding；演示 1.0.3 会真点保存，禁止绑到正式站。

需要 Client 能往下点、但 SRM 仍是已回签时：用 `seed_tiandi_drill.py` 种影子实例（`summary.drill.shadow=true`）。影子只保证界面能点，**不能**当成 SRM 待签章。

### 3.4 签章

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 交期齐后点去签章 | 同 |
| RPA | 定位签章按钮后 **不点** | 关掉 `dryRun` 才点 |
| 现在 | **等单据**（同 3.3） | 有待签章且授权后验收 |

### 3.5 回签轮询

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 一般不用点；可「立即回签轮询」 | 同；主路径自动 |
| RPA | 只读回复状态。已回签则进已回签并触发下合同 | 同 |
| 现在 | **可演练**（已回签样例如 `POJS2607170008`） | 待签章→待回签这条要等 3.3/3.4 真跑过 |

待回签阶段**不要**下载合同。只有 SRM「已回签」后才下合同。

### 3.6 下载签章合同

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 已回签后自动，或点「手动触发签章合同下载」 | 同 |
| RPA | 筛已回签+单号 → 详情 → 只点「查看签章」下载 → **真传测试 SDMS** | 同；SDMS 换生产 |
| 现在 | **可演练** | 改 `.env` 前不要传生产 SDMS |

## 4. 对账单 SOP

客服可见主路径：

```text
待创建 → SDMS对账单核准 → 待生成 → 待上传发票 → 提交审核 → 已完成
```

前两步在填单页，还没有流程实例。待生成起才有详情。

**生成演练成功 ≠ 门户有对账单。** 那张本地待生成草稿相对 SRM 是假的，**禁止**改成未对账，也禁止拿它去扫发票。

未对账演练必须另种影子账单，匹配键 = 门户那条未对账的 **对账日期 + 对账总额**。脚本：

```powershell
cd d:\work_space260811\autotask-workspace\service
.\.venv\Scripts\python.exe scripts\seed_official_unchecked_statement.py --yes --check-date 2026-04-01 --check-amount 5768205.32
```

（日期金额必须当时与门户一致。不要用 `seed_tiandi_drill.py` 种对账单。）

### 4.1 待创建：搜收货、勾选

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 选正式演练门户、选入库确认日期、搜索、按行勾选 | 同 |
| RPA | 正式日期面板（开始 00:00:00 / 结束 23:59:59）+ 未提交 + 导出 Excel | 同 |
| 现在 | **可演练** | 不改闸 |

### 4.2 SDMS 对账单核准

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 勾选后点「生成对账单」 | 同 |
| 系统 | 用勾选汇总对 SDMS `check_amount`，无容差 | 同；SDMS 换生产地址 |
| 现在 | **可演练**（测测试 SDMS） | 生产金额以生产 SDMS 为准 |

找不到单或金额不一致：留在填单页，**不落库**。

### 4.3 待生成：SRM 生成对账单

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 详情等 RPA；失败点「重新生成」 | 同 |
| RPA | 勾选行，定位「生成对账单」，trial/可见后 **不点** | 去掉 `dryRun` 才点 |
| 本地 | 仍为待生成草稿 | 成功后才变未对账 |
| 现在 | **可演练**（只证明按钮能点到） | **等授权关闸**。关闸前门户不会多单 |

下一节点不要用这张草稿。用 §4 种子对齐门户已有未对账。

### 4.4 待上传发票：扫描发票

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | 详情选发票（可多次追加、可删，最多 10 张）→ 点「扫描发票」 | 同 |
| RPA | 按日期+金额找未对账 → 收货应付 → 选文件 → **必须点弹窗确定** → 读出发票号/总额 | 同（本来就无 dryRun） |
| 本地 | 回写发票号/总额，阶段仍待上传发票，对账仍未对账 | 同 |
| 现在 | **可演练**（2026-08-21 已在门户未对账行跑通） | 不改闸 |

门户刷新后，未提交的附件会消失。这是 SRM 行为，不是故障。所以提交必须再扫一次。

### 4.5 核对后点提交审核（人）

| | 演练 | 上线 |
| --- | --- | --- |
| 客服 | **必须**把页面上的发票号、发票总额和发票核对。对得上再点「提交审核」 | 同 |
| 系统 | 点提交 = 承认页面上第一次扫描的结果。文件若已更换，要先再扫 | 同 |
| 现在 | **要人核对后点**。RPA 不会替你看发票 |

### 4.6 提交审核（RPA）

| | 演练 | 上线 |
| --- | --- | --- |
| RPA | 再扫同一批文件（含确定）→ 发票号/总额必须等于页面 → trial click「提交审核」→ **不真点** | 同一包，去掉 `dryRun` 后一致才真点 |
| 本地 | 仍待上传发票 / 未对账；不传发票到 SDMS | 变为已对账 / 审批中；再按 v3.02 把发票传到 SDMS |
| 现在 | **可演练**（2026-08-21 dryRun SUCCESS） | **等授权关闸** 才是真提交 |

二次扫描对不上：失败，不点门户提交。

## 5. 按「现在能不能点」分类

### 5.1 现在就能在 Client 演练

选门户 **天地伟业-国际-正式演练**：

1. 客户订单扫单（可能扫到样例已回签单）。
2. 建测试 SDMS 销售订单。
3. 对已回签样例做回签探测、点「查看签章」下合同并传到测试 SDMS。
4. 对账单填单：搜未提交收货、勾选、走 SDMS 核准。
5. 生成对账单演练（只定位按钮，门户不新增对账单）。
6. 用种子对齐的未对账单：扫描发票、核对后点提交审核（门户不提交）。

### 5.2 必须用户自己看完再点

这些不是缺开发，是业务闸：

| 动作 | 看什么 |
| --- | --- |
| 对账单「扫描发票」 | 先选对的发票文件 |
| 对账单「提交审核」 | 页面发票号、发票总额是否和发票一致 |
| 填单「生成对账单」 | 勾选行、日期是否就是本月要立账的收货 |
| 客户订单重试/手动下合同 | 是否点在正确的那张单上 |

### 5.3 等正式站有单，或等上线授权

| 缺什么 | 才能做什么 | 现在不要做什么 |
| --- | --- | --- |
| 正式站出现真实「待签章」 | 填交期演练（定位保存）、签章演练（定位签章） | 拿已回签单编造填写/签章成功 |
| 授权关掉生成 `dryRun` | 门户真生成未对账单 | 把待生成草稿改成未对账去扫发票 |
| 授权关掉提交 `dryRun` | 门户真提交审核，本地变已完成 | 把 dryRun 成功当成 SRM 已对账 |
| 授权关掉填交期/签章 `dryRun` | 真保存、真签章 | 在演练 Binding 上关闸 |
| 生产 SDMS / ERP 地址 | 上线写生产 | 演练继续打测试 SDMS |
| 扫单 Binding 收掉样例 `searches` | 生产空列表不再扫出演练单 | 带着 `treatAsPending` 上生产 |

## 8. 给客服的最短操作单（演练当天）

**对账单（已跑通的路径）**

1. 选「天地伟业-国际-正式演练」。
2. 打开种子种下的那张未对账（日期、金额与门户一致）。
3. 选发票 → 扫描发票 → 看详情发票号/总额。
4. 和发票核对无误 → 提交审核。
5. 任务 SUCCESS、仍显示未对账 / 演练未提交 → 正确。

**客户订单（已回签样例）**

1. 扫单（无待签章时会带出样例单）。
2. 等建测试 SDMS。
3. 不要填交期、不要签章。
4. 已回签后等下合同，或点手动下载。合同进测试 SDMS → 正确。

**不要做**

- 不要在正式 SRM 上手动点保存、签章、生成对账单、提交审核来「帮 RPA」。
- 不要把待生成草稿拿去扫发票。
- 不要在未关 `dryRun` 时要求本地变成已对账。
