# AutoTask v5.1 权限设计（定稿）

| 项 | 内容 |
| --- | --- |
| 版本 | **v5.1** |
| 状态 | **2026-08-21 定稿**；Auth `/me` 管理员字段与下属接口已到（2026-08-25）；归属人下拉改走下属接口现拉（2026-08-27） |
| 原则 | 门户只认归属人；你能看的门户 = 归属人是你自己，或归属人是你管理的人。`is_super_admin` / `is_task_admin` / `portal_org_role=admin` 全放开。不再用 `portal_access_grants` 做鉴权。 |

---

## 1. 人从哪来

同一套组织，Auth 管人，Task 只管门户归属和按人过滤。

| 角色（口头） | Auth | 在 AutoTask 里 |
| --- | --- | --- |
| 客服 | 普通人 | 只看归属人是自己的门户和单据 |
| 客服主管 / 各组主管 | 在 Auth 里管一批人（**不是** `portal_org_role=admin`） | 看：自己的 + 自己所管的人当归属人的门户和单据 |
| 采购（以后） | 另一批人、另一批主管 | 同一规则，不新做权限系统 |
| 开发 | 普通人 | 同客服：没归到自己名下就看不见业务门户 |
| 组织 admin | `portal_org_role=admin` | **全部放开**（所有门户、任务、订单、对账单） |
| 模块管理员 | `is_task_admin` | 同组织 admin：AutoTask 内全部放开 |
| 超管 | `is_super_admin` | 同 admin，全部放开 |

组与组不靠在门户上勾人。主管能看哪些单，完全取决于 Auth 说「你管谁」+ 门户归属人是谁。

## 2. Auth 接口（Task 登录时缓存）

`GET /api/v1/auth/me` 增加管理员字段：

| 字段 | 含义 | 在 AutoTask 里 |
| --- | --- | --- |
| `is_super_admin` | 超管 | 全部放开，可操作任何权限 |
| `is_task_admin` | AutoTask 模块管理员（如 IT 运维） | **本模块内全部放开**（门户/任务/订单/对账单/调度/模板） |

`GET /api/v1/members/{登录人id}/subordinate` 的 `data` 按登录人角色返回**当前能看见的人**（id、姓名、工号）：

| 角色 | 接口返回 |
| --- | --- |
| 管理员（超管 / 模块管理员 / 组织 admin） | 组织全部员工 |
| 领导 | 自己 + 下属 |
| 普通人 | 自己 |

- AutoTask 登录同步 `/me` 时：写入 `is_super_admin` / `is_task_admin`，并始终拉下属名单写入 `managed_user_ids`（模块管理员也写，方便核对组织关系）。**列表/详情权限过滤继续用这份登录缓存**，不每次打 Auth；超管/模块管理员看数仍全放开，不靠这份名单。
- 下属接口失败时：若 `/me` 里另有管人字段则回退；否则管人列表当空。非 admin 只能看到归属人是自己的门户。超管/模块管理员不受影响。

不要用 `GET /api/v1/auth/users`（超管全站用户）。**不要用** `GET /api/v1/orgs/{org_id}/members`（组织全员）。

## 3. 门户怎么管

### 3.1 字段

| 字段 | 含义 | 管不管权限 |
| --- | --- | --- |
| `created_by` | 创建人，只审计，不再改来当归属 | 否 |
| `owner_user_id` **（新增）** | 当前归属人 | **是，唯一鉴权键** |

新建：`owner_user_id = 当前用户`。已有门户回填 = `created_by`。

**改归属人（Client 必须把归属人放出来）：**

| 谁 | 下拉能选谁 |
| --- | --- |
| 普通人 | 只有自己 |
| 领导（有「管理的人」） | 自己 + 自己管理的所有人 |
| `is_task_admin` / `is_super_admin` / `portal_org_role=admin` | 组织全部员工 |

打开门户编辑/选择归属人时，**现拉** `GET /api/v1/members/{登录人id}/subordinate`（Auth 已按角色返回全员/自己/自己+下属）。**不读登录缓存的 `managed_user_ids`**，也不打组织全员接口。

普通人把字段亮出来，但不能把门户转给别人。领导才能改到自己管的人。Task 按同一规则校验，不能只靠前端藏选项。

归档工号从归属人取（`username`），去掉写死工号。

### 3.2 谁能看见这个门户

```
admin / 超管 / 模块管理员 → 全部
其他人           → owner_user_id == 自己
                 或 owner_user_id 在「我管理的人」缓存里
```

**`portal_access_grants` 去掉鉴权功能。** 门户不按权限表勾人。表本期保留不删，以免大迁移；代码不再读它过滤列表。

### 3.3 任务 / 订单 / 对账单

和门户同一套过滤：先算出能看见的门户 ID，再滤单据。不看任务 `created_by`（调度器经常写在那）。改 URL 也不能越权。

流程模板：不跟门户走。组织内可读；改/删仍限 `admin`/`operator`/超管（原第 5 条）。

## 4. 换组和 10 个客户

不在每个门户上勾 10 遍人。

- 10 个客户归张站：10 个门户归属人都是张站。主管只要在 Auth 里管张站，一次登录缓存就能看见这 10 个。
- 张站调组：Auth 改「谁管张站」。不用改 10 个门户。
- 天地伟业改给李四：只改那一个门户的归属人。
- 采购接手某些客户：门户归属人改成采购那边的人；采购主管在 Auth 里管那些人即可。

## 5. 要改什么（实施时）

**Auth（本仓库外，已提供）**

- `/me` 返回 `is_super_admin`、`is_task_admin`。
- `GET /api/v1/members/{user_id}/subordinate` 按角色返回可见人员（管理员全员、领导自己+下属、员工自己）。

**Task**

- 门户加 `owner_user_id`（已迁）。
- 登录同步 `/me` 缓存管理员标志；再拉下属写入 `managed_user_ids`。
- `user_cache.is_task_admin` 列须授权才迁库。
- 列表/详情：门户、任务、订单实例、对账单按第 3.2 节过滤。
- 代理归属人下拉：打开选择时现拉 `/members/{id}/subordinate`（Auth 已按角色返回可见人员）。登录缓存只做列表权限，不填下拉。选项展示「姓名（工号）」，可搜索。
- 停用 grants 鉴权；归档工号改走归属人。

**Client**

- 门户列表/详情/编辑**必须展示归属人**。
- 下拉打开时现拉可见人员（普通人自己；领导自己+下属；模块管理员/超管全员），展示姓名（工号），可搜索。不复用登录人员缓存。
- 不做「可见人」勾选。
- 不做人员编制页。

**不做**

- 主管树在 AutoTask 里维护。
- 用 `portal_org_role=admin` 表示客服主管。
- 搬 Auth 进本仓库。
- 改 Engine。

## 6. 验收

- 客服只看见归属人是自己的门户和单据。
- 主管看见自己的 + 所管的人的门户和单据；看不见别的组。
- `portal_org_role=admin`、`is_task_admin`、`is_super_admin` 看见全部。
- 改归属人后，原归属人立刻看不见（除非他还在新归属人的「被管」关系里，或他是 admin）。
- 任务/对账单/订单与门户过滤一致。
- 权限表不再影响能不能看见。
- 普通人门户页能看到归属人，下拉只有自己。
- 领导能把归属人改成自己管理的人；改完后按新归属人过滤。
- 下属接口失败时：非 admin 仅见自己名下；超管/模块管理员仍全开。
