## 1. 相对 v2.0 的变更清单（Changelog）

### 1.1 产品行为（相对 v2.0 正文）

| # | 主题 | v2.0 原文要点 | v2.01 实际 / 修订 |
|---|------|---------------|-------------------|
| 1 | 新旧链关系 | 「废弃后继自动链」 | **并存**：旧三任务 successor 链保留不动；流程实例走独立状态机与按钮触发 |
| 2 | 流程模板配置化 | 可配置 SOP 模板 JSON / 非 hardcode | **第一期硬编码** `srm_customer_order` + `STAGE_DEFINITIONS`；无模板管理 UI（与实施计划一致） |
| 3 | 节点2提交方式 | 仅「按行保存」 | **按行保存 + 表头「保存全部」**：可先填多行再一次提交；底层仍按行调 API、每行一次 RPA 子任务 |
| 4 | 节点2成功判定 | RPA「校验保存成功」（隐含 SRM 落库可读） | **AutoTask 行状态为真相**：门户点保存出成功提示即 SUCCESS；不以 SRM 刷新后仍显示交期为成败条件（演示门户不落库） |
| 5 | 节点2/3关系 | 分开两节点 | **保持分离**（用户确认）：交期是签章必要条件，但中间可隔很久；禁止「填齐即签章」产品合并 |
| 6 | 节点3页面 | 「同节点2页但交期只读 + 签章按钮」 | **详情页阶段按钮「去签章」**触发子任务；无独立签章编辑页。交期页在 `DATES_COMPLETE` 后只读 |
| 7 | `SIGN_REQUESTED` 按钮 | 「无（等待线下）」 | **可点「已签章订单下载」**（与 `SIGNED` 相同入口）：客服人工确认已回签后主动归档，不自动扫回签 |
| 8 | 列表操作跳转 | 未细述 | 「填写交货日期」**直达** `/processes/$instanceId/dates`；详情订单行为只读预览 |
| 9 | 幂等记录表 | 单独幂等表 `(portal, po_no)` | **不建独立表**：`process_instances` 唯一约束 `(portal_account_id, process_code, biz_key)` 承担幂等 |
| 10 | 签章前交期来源 | 从 SRM 页面复核 | 正式设计仍从门户复核；**演示门户 TEMP**：签章 Flow 可接收 AutoTask 已写交期并签章前回填（联调后必须删除） |

## 2. 设计原则（沿用 v2.0）

| 原则 | 说明 |
|------|------|
| 用户只看到一个流程 | 客服主视图是「流程实例」，不是三个技术任务 |
| SOP 节点驱动 | 固定四节点推进，阶段决定可见按钮 |
| 待人工为主 | 节点2/3/4 由按钮触发后台 RPA |
| 内外系统分离 | SRM 外部真相；SDMS 审批、E签宝线下人工 |
| 按行粒度 | 交期按行状态跟踪；支持分次填写；允许一次提交多行 |

## 3. 对象模型（已实现）

```text
[后台] 扫单子任务（/tasks 列表默认隐藏）
   └─ 定时或手动 → Flow 拉 SRM「待签章」→ 幂等创建流程实例 → 自动进节点1

[前台] 流程实例（客服只看这个）
   节点1 建 SDMS 销售订单     → 自动 RPA（复用 srm_prepare_erp_order）
   节点2 填写交货日期         → 待人工 → /dates 页（行保存 / 保存全部）
   节点3 发起签章             → 待人工 → 详情「去签章」
   节点4 已签章订单下载上传   → 待人工 → 「已签章订单下载」
   结束 ARCHIVED
```

| 概念 | 实现 | 用户可见 |
|------|------|----------|
| 扫单作业 | `automation_tasks.task_type=srm_scan_pending_orders` + `ScanScheduler` / 手动 scan API | 否（任务列表过滤） |
| 流程实例 | `process_instances` | 是 |
| 行状态 | `process_line_items` | 是（详情/交期页） |
| 子任务 | `automation_tasks.process_instance_id` + `rpa_runs` | 详情中列表，可进任务/Run |

## 4. SOP 节点（v2.01 行为）

### 节点 1：建 SDMS 销售订单

| 项 | 内容 |
|------|------|
| 触发 | 扫单成功创建实例后自动创建子任务 |
| Flow | `rpa_flow_supplier_portal_prepare_erp_order`（当前联调 Binding 指向已发布版本，如 1.2.5） |
| 成功 | 落行 → 阶段 `SDMS_CREATED` |
| 失败 | 实例 `FAILED`（整单失败，不回滚） |

### 节点 2：填写交货日期

| 项 | 内容 |
|------|------|
| 入口 | 列表/详情「填写交货日期」→ **`/processes/{id}/dates`** |
| 页面 | 头信息 + 明细表 + 每行日期；行内「保存」；表头「保存全部（N）」 |
| API | `POST /process-instances/{id}/lines/{lineNumber}/date`（批量=前端顺序多次调用） |
| Flow | `rpa_flow_srm_fill_line_delivery_date` **1.0.2** |
| 成功条件 | 门户保存成功提示；写回 AutoTask `WRITTEN`；**不要求** SRM 刷新后仍有交期 |
| 行状态 | `PENDING` / `SUBMITTING` / `WRITTEN` / `WRITE_FAILED` |
| 进入节点3 | 全部行为 `WRITTEN` → `DATES_COMPLETE` |

### 节点 3：发起签章

| 项 | 内容 |
|------|------|
| 入口 | 详情「去签章」 |
| Flow | `rpa_flow_srm_sign_order`（正式复核门户交期；演示 **TEMP 1.0.1** 可回填 AutoTask 交期） |
| 期望 SRM | 待回签 / 已回签 |
| 主任务 | 成功则 `SIGN_REQUESTED`（当前演示门户签章常不落库 → Run 可能 `WAITING_HUMAN`，实例可仍停在 `DATES_COMPLETE`） |

### 节点 4：已签章订单下载上传

| 项 | 内容 |
|------|------|
| 入口 | `SIGN_REQUESTED` 或 `SIGNED` 下「已签章订单下载」 |
| Flow | `rpa_flow_supplier_portal_upload_order_attachment`（按钮触发，不走旧 successor） |
| 完成 | `ARCHIVED` |

## 5. 阶段与按钮（Client / service 对齐）

| 阶段标识 | 显示名（进度条/列表） | 主按钮 |
|----------|------------------------|--------|
| `CREATING_SDMS` | 建 SDMS 销售订单 | 无 |
| `SDMS_CREATED` | 填写交货日期 | 填写交货日期 → dates |
| `DATES_PARTIAL` | 填写交货日期 | 填写交货日期 → dates |
| `DATES_COMPLETE` | 发起签章 | 去签章 |
| `SIGN_REQUESTED` | 待双方签章完成 | 已签章订单下载 |
| `SIGNED` | 待上传附件 | 已签章订单下载 |
| `ARCHIVED` | 已完成 | 无 |
| `FAILED` | 失败 | 重试（另有取消） |

实例状态：`ACTIVE` / `COMPLETED` / `FAILED` / `CANCELLED`。

| 表 | 职责 |
|------|------|
| `process_instances` | 主任务；唯一 `(portal_account_id, process_code, biz_key)` |

## 7. API（已实现）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/process-instances` | 列表；可按 stage/status/keyword |
| GET | `/process-instances/{id}` | 详情（行、历史、子任务） |
| POST | `/process-instances/{id}/lines/{lineNumber}/date` | 提交一行交期 |
| POST | `/process-instances/{id}/sign` | 发起签章 |
| POST | `/process-instances/{id}/archive` | 归档下载上传 |
| POST | `/process-instances/{id}/retry` | 失败重试 |
| POST | `/process-instances/{id}/cancel` | 取消 |
| POST | `/process-instances/scan` | 手动扫单（body: portalAccountId） |

扫单调度：`SCAN_JOB_ENABLED`、`SCAN_JOB_CRON_HOUR`（默认 8）、轮询间隔等。

## 9. 已确认事项（v2.0 继承 + v2.01 增补）

### 继承自 v2.0

1. 子任务失败不回滚；可重试/取消  
2. 全部行 `WRITTEN` 才进签章  
3. 扫单默认每天 8 点，可配置  
4. 第一期不自动扫「待回签→已回签」  
5. SDMS 建单失败即整单失败  
6. 同 Portal + 业务键幂等，防重复建实例  

### v2.01 增补确认

7. **交期 ≠ 签章**：节点 2/3 分离，不得合并为「填齐即签」  
8. **演示门户不落库交期时**：节点 2 以 AutoTask + 保存成功提示为准  
9. **TEMP**：签章前 AutoTask 交期回填仅用于联调，门户可持久化后删除（见 §10）
