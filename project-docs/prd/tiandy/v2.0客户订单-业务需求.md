## 现状问题清单

整体勉强能跑通，但是业务流程不符合要求。本质流程模板设计应该 SOP + 自主。

当前问题：

- 用户看到的是三个孤立的技术任务模板（任务一/二/三），不是一条完整的 SOP 流程
- 任务二要求一次填齐全部行交期，不支持按行分次提交
- 任务二 SUCCESS 后自动排队任务三，没有等待内部签章的人工关卡
- 客服无法直观看到一张订单处于哪个 SOP 阶段
- 没有定时扫描 SRM 待签章订单的机制，所有任务需手工创建

## 设计原则

| 原则 | 说明 |
|------|------|
| 用户只看到一个流程 | 客服看到的是「客户订单处理流程」，不是三个技术任务 |
| SOP 节点驱动 | 每个订单主任务按固定节点推进，客服知道当前阶段 |
| 待人工为主 | 多数节点是待人工状态，靠按钮触发后台 RPA |
| 内外系统分离 | SRM 状态是外部真相；SDMS 审批、E签宝盖章是人工环节 |
| 按行粒度 | 交期按行填写、按行提交，不强制一次填齐 |

---

## 系统边界

| 系统 | 我们管什么 | 不管什么 |
|------|------------|----------|
| 客户 SRM | 读待签章列表；下载订单；按行写预计交期；发起签章申请；读回复状态；下载签章版 | E签宝双方盖章过程 |
| 内部 SDMS | 根据客户订单创建销售订单；上传签章版附件 | 审批怎么走、后续单据怎么操作 |

---

## 对象模型

```text
[后台] 扫单流程任务（用户不可见）
   └─ 定时扫 SRM「待签章」列表 → 幂等创建「客户订单主任务」

[前台] 客户订单主任务（客服只看这个）
   节点1 建 SDMS 销售订单     → RPA 自动执行
   节点2 填写交货日期         → 待人工 +「填写交货日期」按钮
   节点3 发起签章             → 待人工 +「去签章」按钮
   节点4 已签章订单下载上传   → 待人工 +「下载并上传」按钮
   结束
```

### 关键概念

| 概念 | 职责 | 用户可见 |
|------|------|----------|
| 扫单流程任务 | 每天定时扫 SRM 待签章列表，为新 PO 创建主任务 | 否 |
| 客户订单主任务 | 跟一张 PO 从下载到附件归档的整条 SOP | 是 |
| 子任务 | 各节点背后的 RPA 执行单元 | 折叠在主任务详情里 |

## SOP 节点清单（定稿）

### 节点 1：建 SDMS 销售订单

| 项 | 内容 |
|------|------|
| 触发 | 扫单任务发现 SRM 待签章订单后自动创建主任务并进入本节点 |
| 执行方 | RPA（复用现有任务一 Flow） |
| 动作 | 登录 SRM → 下载订单 XLSX → 对账 → 调用 ERP/SDMS 接口创建销售订单 |
| 完成条件 | SDMS 销售订单创建成功，返回订单号 |
| 完成后状态 | 主任务进入节点 2，状态「待人工-待填写交货日期」 |
| 失败处理 | 主任务状态「失败」，可人工重试 |

### 节点 2：填写交货日期

| 项 | 内容 |
|------|------|
| 状态 | 待人工 |
| 客服操作 | 点击「填写交货日期」按钮 |
| 页面内容 | 我们开发的页面：客户订单头信息 + 明细行表（行号、料号、品名、数量、需求日期）+ 每行预计交货日期输入框 |
| 提交方式 | **按行提交**：用户填完某行日期 → 点该行「保存」→ 触发该行子任务 |
| 子任务动作 | RPA 登录 SRM → 打开订单详情 → 只写该行交期 → 校验保存成功 |
| 行状态 | 每行独立标记：未填写 / 填写中 / 已写入 / 写入失败 |
| 进入下一节点条件 | **全部行**都已写入成功 |
| 分次填写 | 支持：今天填 2 行，明天填 3 行，系统记住每行状态 |

### 节点 3：发起签章

| 项 | 内容 |
|------|------|
| 状态 | 待人工 |
| 进入条件 | 节点 2 全部行交期已写入 |
| 客服操作 | 点击「去签章」按钮 |
| 页面内容 | 同节点 2 页面，但交期只读；显示「签章」按钮 |
| 子任务动作 | RPA 登录 SRM → 打开订单详情 → 复核全部行交期已填 → 点击「签章」发起申请 |
| 完成后 SRM 状态 | 待回签 |
| 完成后主任务状态 | 待人工-待双方签章完成 |
| E签宝 | 线下进行，系统不管；印章管理员和客户在线下完成 |

### 节点 4：已签章订单下载上传

| 项 | 内容 |
|------|------|
| 状态 | 待人工 |
| 进入条件 | 客服确认 SRM 已变为「已回签」（暂定不定时自动扫描，由客服人工确认） |
| 客服操作 | 点击「已签章订单下载」按钮 |
| 子任务动作 | RPA 登录 SRM → 下载签章版订单 → 调用 SDMS 附件上传接口 → 校验上传成功 |
| 完成后 | 主任务状态「已完成」，整条 SOP 结束 |

## 客服视角

### 列表页

客服看到的是「流程实例」列表，不是技术任务列表。**列表页通用，不针对特定客户：**

| 列 | 说明 |
|------|------|
| 业务键 | 由流程模板定义，如客户订单号 `POJS2607130002` |
| 流程类型 | 如 `srm_customer_order`（SRM 客户订单处理） |
| 当前阶段 | 由流程模板定义的阶段名，如「待填写交货日期」 |
| 进度摘要 | 由流程模板定义，如「3/8 行已填」 |
| 状态 | 待人工 / 执行中 / 失败 / 已完成 |
| 更新时间 | 最后操作时间 |
| 操作按钮 | 根据当前阶段显示对应按钮 |

### 详情页

类似审批流程的节点视图，**节点由流程模板配置，不 hardcode**：

```text
┌─ 任务信息 ─────────────────────────────────────┐
│  任务ID: xxx                                    │
│  流程类型: srm_customer_order                   │
│  业务键: POJS2607130002                         │
│  当前阶段: 待填写交货日期                        │
│  [填写交货日期] ← 阶段按钮                       │
└────────────────────────────────────────────────┘

┌─ 流程节点（由流程模板定义）─────────────────────┐
│  ① 建单 ✅  →  ② 填交期 📝  →  ③ 签章 ⏸  →  ④ 归档 ⏸ │
└────────────────────────────────────────────────┘

┌─ 子任务/执行记录（可展开）──────────────────────┐
│  ▼ 节点① 建单子任务                             │
│     Run ID: xxx  状态: SUCCESS  时间: 10:30      │
│     [查看日志] [查看证据]                        │
│  ▶ 节点② 行10 交期写入子任务                     │
│  ▶ 节点② 行20 交期写入子任务                     │
└────────────────────────────────────────────────┘

┌─ 原始输入/输出（可展开）────────────────────────┐
│  input: {...}  output: {...}                    │
└────────────────────────────────────────────────┘
```

### 追查链路

客服点击「查看日志」或「查看证据」→ 跳到现有 Run 详情页：

- Run 事件列表（STEP_STARTED / STEP_SUCCEEDED / STEP_FAILED）
- Artifact 列表（截图、XLSX）
- 错误信息

**复用现有 Run/Artifact 查看器，不为特定客户单独做日志页。**

### 阶段状态汇总

| 阶段标识 | 显示文案 | 可点击按钮 |
|----------|----------|------------|
| `CREATING_SDMS` | 建单中 | 无（等待） |
| `SDMS_CREATED` | 待填写交货日期 | 填写交货日期 |
| `DATES_PARTIAL` | 待填写交货日期（X/N 行已填） | 填写交货日期 |
| `DATES_COMPLETE` | 待签章 | 去签章 |
| `SIGN_REQUESTED` | 待双方签章完成 | 无（等待线下） |
| `SIGNED` | 待上传附件 | 已签章订单下载 |
| `ARCHIVED` | 已完成 | 查看证据 |
| `FAILED` | 失败 | 重试 / 取消 |

## 流程模板配置化

新增「流程模板」概念（SOP 模板，非 WorkflowTemplate）：

```json
{
  "code": "srm_customer_order",
  "name": "SRM 客户订单处理",
  "stages": [
    { "id": "create_sdms", "name": "建 SDMS 销售订单", "auto": true },
    { "id": "fill_dates", "name": "填写交货日期", "auto": false, "button": "填写交货日期" },
    { "id": "sign", "name": "发起签章", "auto": false, "button": "去签章" },
    { "id": "archive", "name": "已签章订单下载上传", "auto": false, "button": "已签章订单下载" }
  ],
  "listColumns": ["po_no", "customer_name", "stage", "progress"],
  "detailStages": ["create_sdms", "fill_dates", "sign", "archive"]
}
```

**天地伟业只是第一个使用此模板的客户；其他客户（如华为、中兴）复用同一模板，仅 Portal 和参数不同。**

## 数据模型（通用）

| 表 | 职责 | 通用性 |
|------|------|--------|
| `process_instances` | 主任务：流程类型、业务键（po_no）、当前阶段、状态 | 任何流程 |
| `process_stage_history` | 阶段变更记录：何时进入/离开某阶段 | 任何流程 |
| `process_line_items` | 行级状态（可选）：行号、状态、子任务ID | 需要行级跟踪的流程 |
| `automation_tasks` | 现有子任务表，关联到 `process_instances` | 复用 |
| `rpa_runs` | 现有 Run 表，关联到子任务 | 复用 |

**不建客户专属表（如 `tiandi_orders`），所有客户共用通用结构。**

## 与现有三任务的关系

| SOP 节点 | 复用/改造 |
|----------|-----------|
| 扫单（不可见） | **新建** Flow：登录 SRM → 拉待签章列表 → 幂等创建主任务 |
| 节点 1 建 SDMS 销售订单 | 复用现有任务一 Flow（`srm_prepare_erp_order`） |
| 节点 2 按行写交期 | **改造**现有任务二：拆成按行写入（单行 update），不再强制全量 |
| 节点 3 发起签章 | **拆出**现有任务二的签章部分，独立成「只签章」Flow |
| 节点 4 下载上传 | 复用现有任务三 Flow（`srm_upload_order_attachment`），改为按钮触发 |

### 关键改动

1. **废弃后继自动链**：不再任务一 SUCCESS 自动创建任务二 DRAFT、任务二 SUCCESS 自动排队任务三
2. **主任务状态机**：用 `sop_stage` 字段驱动节点流转，按钮触发子任务
3. **按行子任务**：交期按行写入，每行独立状态
4. **人工关卡**：签章后等待线下 E签宝，不自动往下走

## 已确认事项

| 项 | 决策 | 说明 |
|------|------|------|
| 1 | 子任务失败不回滚 | 子任务是整单的一个状态节点；失败说明到了某个节点需要人工重试或取消，已成功的行保留 |
| 2 | 全部交期填完才进签章 | 进入订单详情页时行数已知；以我们系统记录的行状态为准，全部「已写入」才进入签章节点 |
| 3 | 扫单频率 | 每天早上 8 点一次，可配置 |
| 4 | 不自动扫「待回签→已回签」 | 第一期不做定时扫描，由客服人工确认 SRM 已回签后点按钮 |
| 5 | SDMS 建单失败即整单失败 | 建单失败则后续节点无意义，主任务状态为失败，只有成功才进入下一阶段 |
| 6 | 需存表记录已创建的 PO | 防止重复创建主任务；同 Portal + po_no 幂等；扫单时先查记录表，已存在则跳过 |

## 幂等记录表

扫单任务每次发现 SRM 待签章订单时，先查记录表：

| 字段 | 说明 |
|------|------|
| `portal_account_id` | Portal 账号 |
| `po_no` | 客户订单号 |
| `process_instance_id` | 已创建的主任务 ID |
| `created_at` | 创建时间 |

**唯一约束**：`(portal_account_id, po_no)`，重复扫到直接跳过。
