# 产品系统概览与架构边界

## 组成

| 模块 | 默认端口 | 主要职责 |
| --- | ---: | --- |
| Auth / nodeskclaw-backend | 4510 | 登录、JWT、用户、组织与权限上下文 |
| Task / nodeskclaw-task | 4520 | Portal、模板、Binding、任务、Run、Artifact、Worker 契约与后继任务 |
| RPA Engine | 4610 | Flow Registry、Worker、lease、浏览器 Runtime、Artifact 采集与结果回调 |
| SMC-Copilot Client | 桌面程序 | 调用 Auth/Task，展示和维护业务数据；部分 Engine 管理能力仍在建设 |
| RPA Flow | 由 Engine 加载 | 实现具体门户自动化，不自行启动浏览器、不保存凭据 |
| PostgreSQL | 5432 | Auth 独立库；Task 与 Engine 共库分 Schema |
| MinIO 或 S3 兼容存储 | 环境决定 | Flow ZIP、Runtime Artifact 或签名上传对象 |

## 主调用链

```text
Client -> Auth(登录/JWT)
Client -> Task(业务操作)
Task -> Auth /me(校验用户与组织)
Task -> Engine(精确 Binding 校验、包版本查询)
Engine -> Task Worker API(register/heartbeat/lease/renew/event/artifact/finish)
Engine -> 供应商门户(托管 Chrome 执行 Flow)
```

Task 的“开始任务”接口只创建或推进 Run；真正执行由 Engine 主动 lease。系统没有供用户直接调用的 Engine `/run` 入站接口。

## 数据边界

- Auth 使用独立数据库，例如 `nodeskclaw_backend_local`。
- Task 与 Engine 使用 `nodeskclaw_task`；Task 表位于 `public`，Engine 九张表位于 `rpa_engine`。
- Engine 连接必须显式使用 `rpa_engine,public` search path；不得修改数据库用户的全局 search path。
- Flow Registry 的版本 UUID 和 checksum 是不可变快照。Task Binding 必须保存精确版本，不得用“最新版本”替代。
- Portal 只保存门户地址、登录账号标识和 `credentialRef`；门户密码不得进入 Task、Client 或 Flow 包。

## 已实现与边界

当前已具备 Portal、模板、精确 Binding、任务与 Run、DRAFT 待填写、Artifact 预览/下载、Task1→Task2→Task3 后继机制，以及 Engine Registry、Worker、Runtime 和 MANAGED Chrome 执行链。

当前演示仍属于内部测试基线。生产级服务账号鉴权、集中凭据服务、可靠 Callback Outbox、Worker/Flow 操作系统级隔离、队列公平性和可恢复的同一浏览器人工处理尚未闭环。
