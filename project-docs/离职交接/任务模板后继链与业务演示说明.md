# 任务模板后继链与业务演示说明

## 三任务业务链

| 步骤 | 模板 code | 输入 | 后继 |
| --- | --- | --- | --- |
| 任务一：下载并推送订单 | `srm_prepare_erp_order` | `po_no` | 创建任务二 |
| 任务二：填写交货日期并确认 | `srm_update_expected_delivery_dates` | `po_no`、`order_lines` | 创建并排队任务三 |
| 任务三：上传订单附件 | `srm_upload_order_attachment` | 映射后的 `po_no` 等 | 无 |

任务一输出 `ORDER_DOWNLOAD_PUSH_OUTPUT_V1`，由 `ORDER_DELIVERY_CONFIRMATION_V1` 映射成任务二。任务二以 `DRAFT` 创建，在 Client“待填写”页签维护每行 `expected_delivery_date`，提交并运行后才写门户。

任务二输出 `ORDER_DELIVERY_CONFIRMATION_OUTPUT_V1`，由 `ORDER_ATTACHMENT_UPLOAD_V1` 映射成任务三。任务三以 `QUEUED` 创建并生成 Run。当前只支持这两个 mapper，不是通用编排器。

## Binding 配置

任务一：

```json
{"successor":{"on":"SUCCESS","targetWorkflowBindingId":"<任务二Binding ID>","inputMapper":"ORDER_DELIVERY_CONFIRMATION_V1"}}
```

任务二：

```json
{"successor":{"on":"SUCCESS","targetWorkflowBindingId":"<任务三Binding ID>","inputMapper":"ORDER_ATTACHMENT_UPLOAD_V1"}}
```

来源与目标必须属于同一租户、同一 Portal；目标 Binding 已启用、有精确 Flow 快照且不能自引用。Task 迁移完成后设置 `SUCCESSOR_JOB_ENABLED=true`。

## 演示准备

1. 发布三个版本；当前重点是任务一 `1.2.2`（`1.2.3` 待复验）、任务二 `1.3.0`、任务三 `1.0.1`。
2. 为同一 Portal 创建并启用三个模板、三个 Binding。
3. 从后向前配置 successor：任务三、任务二、任务一。
4. Engine ready、Worker 在线、队列无无关 Run。
5. 只手工创建任务一并填 `po_no`。

## 观察

- `/tasks/{taskId}/runs`：Run；`/runs/{runId}` 和 `/events`：状态与错误。
- `/tasks/{taskId}/successors`：后继作业；失败后调用 `/successors/{jobId}/retry`。
- `/tasks/{taskId}/artifacts`：证据。
- 无任务二：检查 output schema、successor 配置、处理器开关和后继错误。
- 任务二无有效 `order_lines`：检查任务一输出，用户不应手工重录整张订单。

后继创建有幂等约束；门户签章/上传等副作用仍须由 Flow 保证幂等。
