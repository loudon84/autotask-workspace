# 全新机器部署与初始化手册

## 一、安装依赖并拉取代码

安装 PostgreSQL 16、Git、Python 3.12、uv、Node.js LTS、Chrome/Chromium。需要远程桌面端时开放 4510、4520；Task 与 Engine 同机时 4610 可只监听本机。

```powershell
cd D:\AutoTask-Workspace
git clone -b v0.1 https://github.com/YuweiSu529/nodeskclaw.git
git clone -b v0.1 https://github.com/loudon84/copilot-rpa.git rpa-engine
git clone -b v0.1 https://github.com/YuweiSu529/copilot-autotask.git app
```

Flow 工作区不在上述仓库中，必须从交接存储取得，并校验 ZIP/hash 后放到 `rpa-flows`。

## 二、创建数据库

推荐创建 Auth 独立库 `nodeskclaw_backend_local`，以及 Task/Engine 共用库 `nodeskclaw_task`。密码由管理员现场替换；`CREATE DATABASE` 在 DBeaver 自动提交模式下逐条执行。

```sql
CREATE ROLE nodeskclaw_backend_local LOGIN PASSWORD '<现场设置强密码>';
CREATE DATABASE nodeskclaw_backend_local OWNER nodeskclaw_backend_local ENCODING 'UTF8' TEMPLATE template0;

CREATE ROLE task_user LOGIN PASSWORD '<现场设置强密码>';
CREATE DATABASE nodeskclaw_task OWNER task_user ENCODING 'UTF8' TEMPLATE template0;
```

连接到 `nodeskclaw_task` 后执行：

```sql
CREATE SCHEMA IF NOT EXISTS rpa_engine AUTHORIZATION task_user;
```

## 三、配置与迁移 Auth

```powershell
cd D:\AutoTask-Workspace\nodeskclaw\nodeskclaw-backend
Copy-Item .env.example .env
uv sync
```

`.env` 至少配置 `DEBUG=false`、本地 `DATABASE_URL`、强随机 `JWT_SECRET`、`ENCRYPTION_KEY`、`INIT_ADMIN_ACCOUNT=admin`、`RESET_ADMIN_PASSWORD=false`、`DATABASE_NAME_SUFFIX=` 和 `SKIP_AUTO_MIGRATE=1`。AutoTask 最小闭环不需要配置 LLM Proxy、K8s、Gene 或邮箱。

```powershell
uv run alembic upgrade head
uv run alembic current
```

## 四、配置与迁移 Task

```powershell
cd D:\AutoTask-Workspace\nodeskclaw\nodeskclaw-task
Copy-Item .env.example .env
uv sync
```

必须配置本地 `DATABASE_URL`、与 Auth 完全相同的 `JWT_SECRET`、`NODESKCLAW_BACKEND_URL=http://127.0.0.1:4510`、`RPA_ENGINE_BASE_URL=http://127.0.0.1:4610`、`RPA_ENGINE_VALIDATE_BINDING=true`、`SEED_DATA_ENABLED=false`、`SKIP_AUTO_MIGRATE=1`。可先使用本地 Artifact；后继任务迁移完成后再启用 `SUCCESSOR_JOB_ENABLED=true`。

```powershell
uv run alembic upgrade head
uv run alembic current
```

## 五、配置与迁移 Engine

按照 [Engine 全新机器部署手册](../../rpa-engine/docs/离职交接/引擎全新机器部署手册.md) 创建 `.venv`、安装 Playwright、配置同一个 `nodeskclaw_task` 数据库和 `rpa_engine` Schema，并显式执行：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
```

期望 Engine revision 为 `20260713_0001`。已有九张表但没有版本表时禁止直接 upgrade，必须先做结构漂移检查。

## 六、启动顺序

1. PostgreSQL、MinIO/S3。
2. Auth 4510，记录首次 admin 随机密码并立即改密。
3. Task 4520。
4. Engine 4610，先关闭 Worker/Runtime/lease 验证依赖，再分阶段开启。
5. 上传、校验、发布 Flow；创建 Portal、模板和精确 Binding。
6. 启动 Client 或安装内部测试包。

## 七、首次验收

四个健康/OpenAPI 地址可访问；admin `/me` 有当前组织；Task 可查询 Portal；Engine ready 全部必需依赖健康；Worker 在线；只创建一个测试任务完成 SUCCESS；截图可预览、XLSX 可下载；重启后数据与迁移版本保持不变。
