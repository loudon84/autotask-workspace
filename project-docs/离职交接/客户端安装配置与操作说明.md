# 客户端安装配置与操作说明

## 安装与端点

内部测试包产品名为 `SMC-Copilot`，版本 `0.1.0`，Windows x64、未签名。安装时可能显示“未知发布者”。安装后从开始菜单/桌面快捷方式启动；交付目录中的 `SMC-Copilot.exe` 是安装器，不是每次运行入口。

完整截图版手册见 [SMC-Copilot 内部测试操作手册](../../app/out/delivery/SMC-Copilot-0.1.0-internal-win-x64/SMC-Copilot-0.1.0-内部测试操作手册.md)。安装包同时交付 `SHA256SUMS.txt` 和 `BUILD_INFO.txt`。

开发模式：

```powershell
cd app
npm ci
npm run start
```

默认 remote 端点由构建环境变量决定；高级 endpoint 保存于 Electron userData 下的 `autotask-endpoint-config.json`。跨机访问时 Auth/Task 填服务机可达 IP，不能填客户端自己的 `127.0.0.1`。修改后退出并重开 Client。

## 当前操作能力

- 登录、Dashboard 和任务列表。
- Portal 新建/编辑/禁用/软删除；表单可填写 `credentialRef`，但不录入门户密码。
- Workflow Template 新建、启用、禁用和安全软删除。
- Workflow Binding 创建、精确校验和启停。
- 新建、提交、运行、取消和重试任务；DRAFT 显示在“待填写”。
- Task2 使用明细表格维护每行预计交货日期。
- 查看 Run、事件、后继作业和证据；图片预览，图片/XLSX 下载。
- 已有基础 Engine IPC 接入；完整的图形化 Flow Registry 管理页仍非正式交付能力。

## 推荐业务顺序

1. 新建 Portal：填写客户、门户 URL、登录账号标识、唯一 credentialRef、打开模式和 session partition。
2. 新建并启用模板：输入 Schema 使用实际 Flow 的字段名与类型。
3. 在 Portal 详情创建 Binding：选择模板，填写纯 Flow ID 和独立版本号，校验后保存。
4. 新建任务：只选择已启用且匹配 Portal/模板的 Binding。
5. Task1 填 `po_no` 后运行；Task2 由后继机制创建为 DRAFT，在“待填写”维护日期后提交/运行。
6. 在任务详情观察 Run 终态、事件、后继任务和 Artifact。

## 常见问题

- 一直转圈：先看浏览器开发者工具/主进程日志，再分别验证 Auth、Task；常见原因是 DTO 与响应不一致或请求未结束。
- `Cannot read ... map`：通常是接口返回 `data` 为空或分页 DTO 未适配，不能靠重启解决。
- Binding 保存 500：先直接调用 Engine 精确校验，确认版本已发布、UUID/checksum 有效，再看 Task 日志。
- 证据预览或下载 404：检查 Task public/download base URL；返回的 URL 必须从客户端机器可达。
- 时间显示：Client 已按北京时间展示，但数据库和 API 仍建议保存 UTC。

## 构建安装包

只从干净提交构建，不能带入 `.env.development`、Token、`AGENTS.md`、源码临时改动或 Artifact。先运行类型检查、Biome、Vitest，再执行 `npm run make -- --arch=x64`；不要执行 `npm run publish`。交付前检查 ASAR 和 SHA-256，并在另一台机器完成安装、登录、查询、预览、下载、重启和卸载验证。
