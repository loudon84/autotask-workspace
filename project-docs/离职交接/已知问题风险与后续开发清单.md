# 已知问题风险与后续开发清单

## 生产阻断项

| 优先级 | 项目 | 当前状态/完成标准 |
| --- | --- | --- |
| P0 | Worker 生产鉴权 | 测试仍可用 `TASK_AUTH_MODE=none`；需服务账号短期 Token、轮换、401 恢复和审计 |
| P0 | 门户凭据服务 | `mock_env` 只适合单 Portal 测试；需受管凭据服务、租户授权和轮换 |
| P0 | Flow 隔离 | Python Flow 仍在 Engine 进程内；需子进程/容器、硬超时、资源限制和孤儿清理 |
| P0 | Artifact 可靠投递 | 上传与 metadata 仍需可靠 Outbox、幂等、重启恢复和清理闭环 |
| P1 | 调度与回调 | HTTP lease 兼容层需能力路由、公平性、死信；Task 需持久去重并拒绝陈旧 finish |
| P1 | 人工恢复 | 当前 Type-A `WAITING_HUMAN` 会结束会话，人工处理后不能恢复原浏览器继续 |

## 当前演示风险

- 任务一 `1.2.3` 曾在门户明细读取处失败，当前建议用 `1.2.2`；修复后必须重新做真实订单 E2E。
- 任务二 `1.3.0` 到任务三 `1.0.1` 已单独验证，但最新三个版本的一次性 Task1→Task2→Task3 全链仍需新订单复验。
- Task Artifact public/download base URL 若为回环地址，其他电脑无法预览/下载。
- 每个新 Portal 凭据目前通常需要改 Engine 环境变量并重启，不具备产品化动态管理。
- AutoTask 模块尚无正式的内建定时调度界面；定时触发需 Task 调度器或外部系统创建/启动任务。
- Task 后继机制只支持两个固定 mapper，不是通用工作流编排。

## Client 与运维待办

- Client 完整 Flow Registry 图形页面待完善；上传、校验详情、发布确认和生命周期仍以 Postman 为主。
- 403 错误需显示后端 `message_key`，当前“权限不足”提示不利于排障。
- 任务状态刷新需完善推送/稳定轮询、断线恢复和卡住提示。
- 内部安装包未签名；正式分发需代码签名、更新源和版本策略。
- Windows 当前多为手工 PowerShell 启动；同事长期运行应配置受控服务、日志轮转和开机恢复。
- Engine Postman 文件名仍写 v0.5.0，与当前 Engine 0.6.0 不一致。

## 测试待办

Linux 实机 E2E；断网/重启/lease 过期/回调重放；多 Worker/多租户/能力路由；MinIO 中断、磁盘满与大文件；数据库+对象存储联合恢复；Portal DOM/验证码变化回归。

## 不得误报

测试跑通不等于生产安全闭环；`WAITING_HUMAN` 不代表原会话可继续；发布 Flow 不代表 Binding 已切换；finish 成功不代表 Artifact 可靠落库；live 200 不代表可领任务。
