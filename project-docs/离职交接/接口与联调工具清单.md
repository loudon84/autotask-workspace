# 接口与联调工具清单

## 地址与响应格式

- Auth：`http://<host>:4510/api/v1`，登录响应为 `{code,data}`。
- Task：`http://<host>:4520/api/v1/autotask`，响应为 `{code,data}`。
- Engine：`http://<host>:4610`，业务接口直接返回 JSON，不套 Task 信封。

Auth/Task 业务请求使用 `Authorization: Bearer <access_token>`。Engine Registry 请求使用 `X-Actor-Id`；TENANT Flow 再使用 `X-Tenant-Id`。Token 不写入集合初始值或聊天。

## Auth 最小接口

```text
GET  /api/v1/health
POST /api/v1/auth/account-login
GET  /api/v1/auth/me
PUT  /api/v1/auth/me/password
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
```

## Task 业务接口组

```text
/portal-accounts
/workflow-templates
/workflow-bindings
/tasks
/runs
/human-actions
/artifacts
/rpa-workers
```

均加前缀 `/api/v1/autotask`。Worker 专用接口在 `/worker-api` 下，包含注册、心跳、lease、renew、event、Artifact 和 finish；普通用户不要手工调用它们。

## 手工执行和观察顺序

```text
GET  /tasks                         List Tasks
POST /tasks                         Create Task
GET  /tasks/{taskId}                Get Task
POST /tasks/{taskId}/start          Start Task
GET  /tasks/{taskId}/runs           List Task Runs
GET  /runs/{runId}                  Get Run Detail（轮询）
GET  /runs/{runId}/events           List Run Events
GET  /tasks/{taskId}/successors     List Successor Jobs
GET  /tasks/{taskId}/artifacts      List Artifacts
GET  /artifacts/{artifactId}/download-url
```

Task 绑定哪个 Flow，应从任务的 `workflow_binding_id` 查询 Binding，再核对 `rpaFlowId`、版本、精确版本 UUID 和 checksum。Engine 主动 lease 执行，没有 `/run` 入站接口。未来定时任务应由 Task 调度器或外部系统创建/启动 Task，不应直接绕过 Task 调 Engine。

## Engine Registry 接口

上传、校验、发布顺序见[流程包开发注册发布与绑定规范](流程包开发注册发布与绑定规范.md)。观察接口包括 Flow 列表/详情/版本、版本详情、Binding 校验、Worker 列表/详情和包下载 307 跳转。

Engine Postman 集合：`rpa-engine/postman/AutoTask_RPA_Engine_v0.5.0.postman_collection.json`。文件名沿用 v0.5.0，但当前 Engine 为 0.6.0，交接人应后续更新命名并重新做路由完整性测试。

## 联调原则

- 参数名以目标环境 OpenAPI 为准；不要混用历史集合中的 camelCase/snake_case。
- UUID、checksum、tenant、Portal、Binding、Task、Run 均从响应自动保存，不手写旧环境值。
- Package 307 只检查 Location，不把签名 URL保存到集合。
- 写接口默认加保护变量；Runner 不执行 disable、rollback、deprecate 等生命周期动作。
- 每次只保留一个专用 `QUEUED` 测试 Run，避免旧 Mock 数据被 Worker 领取。
