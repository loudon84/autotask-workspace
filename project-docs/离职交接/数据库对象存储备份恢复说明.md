# 数据库对象存储备份恢复说明

## 数据布局

- Auth：独立 PostgreSQL 数据库，包含账号、组织、成员关系、权限和 Auth 平台数据。
- Task：`nodeskclaw_task.public`，包含 Portal、模板、Binding、Task、Run、事件、Artifact、Worker、后继作业等。
- Engine：同库 `nodeskclaw_task.rpa_engine`，九张表为 `rpa_flows`、`rpa_flow_versions`、`rpa_flow_validation_runs`、`rpa_flow_release_audits`、`rpa_worker_instances`、`rpa_execution_attempts`、`rpa_callback_outbox`、`rpa_browser_profiles`、`rpa_cdp_endpoints`。
- Task 关键后继迁移为 `7c1f4d8e2a90`；Engine revision 为 `20260713_0001`。实际以 `alembic current/heads` 为准。

## 备份原则

Auth 数据库和整个 `nodeskclaw_task` 都使用 PostgreSQL custom-format 备份；不要只备份九张 Engine 表，因为 Task 与 Engine 的 ID/快照互相引用。对象存储同时备份 Flow ZIP 和 Artifact，并记录与数据库相同的时间切点。

示例只展示命令结构，密码通过安全环境或交互输入：

```powershell
pg_dump -Fc -h <db-host> -U <auth-role> -d <auth-db> -f <backup-dir>\auth.dump
pg_dump -Fc -h <db-host> -U <task-role> -d nodeskclaw_task -f <backup-dir>\task-engine.dump
```

对象存储使用管理员批准的 `mc mirror`、版本化 bucket 或平台快照。备份清单记录 bucket、对象数量、总大小、数据库 dump hash、时间和操作人，不记录密钥或签名 URL。

## 恢复

1. 先在隔离的空数据库和空 bucket 演练，禁止直接覆盖生产。
2. 核对备份 hash、PostgreSQL 主版本、代码提交和 Alembic heads。
3. 恢复 Auth，再恢复 Task/Engine 共库，再恢复对象存储。
4. 修正目标环境的 owner/grant、公开 base URL 和存储 endpoint。
5. 关闭 Worker lease 启动三服务，执行 health/readiness 和只读数据核对。
6. 抽查 Flow ZIP checksum、Binding 快照、Task/Run、截图与 XLSX。
7. 只在确认无遗留 QUEUED/RUNNING 冲突后开启 lease。

`pg_restore --clean`、覆盖 bucket、删除数据库或直接更新业务状态都是破坏性操作，只能由 DBA/系统负责人书面授权。

## 保留与清理

规定数据库、Artifact、Trace、下载文件和审计日志的保留期。Runtime 临时目录不是备份；确认 Artifact 已进入权威存储并登记元数据后方可清理。定期做恢复演练，不能把“备份命令成功”视为“可恢复”。
