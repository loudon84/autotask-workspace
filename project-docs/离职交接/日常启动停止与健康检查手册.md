# 日常启动停止与健康检查手册

## 启动顺序

PostgreSQL/MinIO → Auth → Task → Engine → Client。不要先打开 Engine lease 再启动 Task。

```powershell
# Auth 4510
cd D:\AutoTask-Workspace\nodeskclaw\nodeskclaw-backend
$env:DEBUG='false'; $env:SKIP_AUTO_MIGRATE='1'
uv run uvicorn app.main:app --host 0.0.0.0 --port 4510

# Task 4520（另开窗口）
cd D:\AutoTask-Workspace\nodeskclaw\nodeskclaw-task
$env:SKIP_AUTO_MIGRATE='1'; $env:SEED_DATA_ENABLED='false'
uv run uvicorn app.main:app --host 0.0.0.0 --port 4520

# Engine 4610（另开窗口）
cd rpa-engine
.\.venv\Scripts\python.exe -m nodeskclaw_rpa_engine

# Client 开发模式（另开窗口）
cd app
npm run start
```

安装版 Client 从开始菜单或桌面快捷方式启动，不需要每次点击交付目录中的安装器。

## 健康检查

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:4510/api/v1/health
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:4520/health
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:4610/health/live
Invoke-RestMethod http://127.0.0.1:4610/health/ready
```

同时检查 `/openapi.json`。Engine 的 `live=200` 只代表进程存活；`ready=200` 且所有 `required=true` 依赖为 `healthy` 才可运行任务。

## 业务预检

- Client 登录成功，`/auth/me` 返回 `current_org_id`。
- Portal、模板和 Binding 均属于当前租户且已启用。
- Binding 指向准确的已发布 Flow UUID/checksum。
- Worker 在线、能力匹配、无重名 `WORKER_ID`。
- 队列无缺少 Flow 快照的旧 `QUEUED` Mock Run。
- Runtime、浏览器目录、Artifact 目录有写权限且磁盘足够。

## 停止顺序

先停止创建新任务，等待 `RUNNING` 清零；关闭 Engine lease，正常停止 Engine 并确认 Worker `OFFLINE`；再停止 Task、Auth，最后停止存储。不得强杀正在执行门户写操作的浏览器。

## 重启后

重新跑健康检查，核对迁移版本、Worker 状态和遗留 `LEASED/RUNNING`。如果外部门户可能已经完成签章/上传，不得直接重试；先人工核对副作用和 Task/Run 终态。
