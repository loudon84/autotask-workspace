# 日志监控故障与应急处置手册

## 最小监控

监控 4510/4520 health、4610 live/ready、Worker 心跳、QUEUED/RUNNING/WAITING_HUMAN/FAILED 数量、lease 续期、Callback Outbox、后继作业重试、Artifact 上传下载、磁盘、数据库连接池和 401/403/409/5xx。

日志关联字段至少保留 Task ID、Run ID、Lease ID、Worker ID、Flow Version ID、tenantId 和时间；禁止输出密码、Token、完整凭据、数据库 URL 或签名 URL。

## 常见问题定位

| 现象 | 优先检查 |
| --- | --- |
| 登录 401 | 账号/密码、实际 Auth endpoint、账号状态 |
| 登录 500 | Auth 日志、数据库迁移、初始组织/管理员种子 |
| 客户 SRM 403 | `/auth/me` 组织/角色、JWT secret、Task 用户同步 |
| Binding 保存 500 | Engine ready、版本 PUBLISHED、精确 UUID/checksum、Task 日志 |
| Worker OFFLINE | Worker 开关、Task 地址、register/heartbeat、重复 Worker ID |
| Task 一直排队 | lease 开关、Worker 能力、旧无效 Run、Flow 快照 |
| Run 很快 FAILED | Run events、Engine attempt、包入口、凭据作用域和门户地址 |
| `WinError 5` | Runtime/下载目录 ACL、文件仍被浏览器占用；不要复用固定临时文件名 |
| 下载到图片而非 XLSX | Artifact 列表中选择正确 mime/name/id，不要默认取第一项 |
| 跨机预览/下载 404 | Task public/upload/download base URL 是否仍为 127.0.0.1 |
| 无任务二/三 | successor 开关、output schema、Binding 配置、后继作业错误 |
| Task2 无 order_lines | Task1 output 是否包含有效完整明细 |

## 故障取证顺序

先记录环境、时间、用户、Task/Run/Binding/Flow Version ID；保存三服务相关日志和非敏感响应；查询 Task、Run、events、successors、artifacts；再查 Engine attempt/outbox。不要先重启或清理，否则会丢失现场。

## 应急处置

- 发现误领取：立即停止创建新任务并关闭 lease，等待当前操作到安全点后正常停 Engine。
- 外部门户副作用不明：标记人工核验，禁止自动 retry。
- 密钥泄漏：撤销/轮换密钥，检查 Git/日志/安装包，记录影响范围。
- 数据库异常：切只读或停止写入口，保存诊断，联系 DBA；禁止临时执行未知 DDL。
- 磁盘满：先停 lease，确认权威 Artifact 已上传后按保留策略清理 Runtime 临时文件。

恢复服务时按存储→Auth→Task→Engine 的顺序，先 lease 关闭验证，再进行单任务灰度。
