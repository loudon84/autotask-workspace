# 测试验收发布与回滚手册

## 代码质量

```powershell
# Auth 或 Task
uv run ruff check .
uv run pytest

# Engine
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m mypy src
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m pip check

# Client
npm run check
npx tsc --noEmit --skipLibCheck
npm test
```

Flow 单测和包校验按各 Flow 目录说明执行。真实门户测试必须使用专用订单和账号，涉及签章/上传时先获得业务授权。

## 发布前检查

1. 工作树差异已评审，无 `.env`、Token、内部地址、ZIP、Artifact、缓存或截图。
2. 数据库迁移经过离线评审，升级/降级或兼容策略明确。
3. Auth/Task JWT、Task/Engine 地址、Artifact public URL 和对象存储配置已核对。
4. Flow 已通过静态校验，UUID/checksum 已登记，Binding 使用精确快照。
5. Worker lease 默认关闭；旧 QUEUED/RUNNING 数据已处理。
6. 备份和回滚责任人已确认。

## 分层验收

- 服务层：Auth/Task health、Engine live/ready、OpenAPI。
- 权限层：admin 登录、`/me` 组织上下文、Portal 读写权限。
- Registry：上传→校验→发布→回读→Binding 校验。
- Client：登录、Portal/模板/Binding、任务、状态刷新、证据预览和下载。
- 运行层：一个 SUCCESS，核对 lease/renew/event/artifact/finish。
- 业务链：任务一成功创建 DRAFT 任务二；填写后任务二成功并排队任务三；任务三终态和幂等行为正确。
- 重启层：服务重启后数据、迁移、Worker 和下载仍正常。

## 发布顺序

先迁移数据库，再部署 Auth/Task，随后 Engine（lease 关闭），发布 Flow 并切换 Binding，最后发布 Client。只放一个灰度任务；观察稳定后逐步放量。

## 回滚

- Client：保留上一安装包和 hash，卸载/安装旧版；endpoint 文件可保留但必须复核。
- Auth/Task/Engine：优先回滚代码到兼容旧数据库的提交。数据库 downgrade 只有迁移明确支持且备份已验证时才能执行。
- Flow：不覆盖旧包；将 Binding 显式切回旧版 UUID/checksum并校验。
- 任务：停止新建和 lease，不直接把外部副作用不明的 Run 改回 QUEUED。

回滚完成后重新执行 health、权限、只读查询和一个受控任务，并在总控记录原因、影响、数据处置和后续修复。
