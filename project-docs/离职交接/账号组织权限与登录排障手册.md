# 账号组织权限与登录排障手册

## 登录与 Token 来源

Token 由 Auth 登录接口返回，不能从数据库或文档取得：

```http
POST http://<Auth主机>:4510/api/v1/auth/account-login
Content-Type: application/json

{account:admin,password:<现场密码>}
```

响应 `data.access_token` 用于后续请求：

```http
GET http://<Auth主机>:4510/api/v1/auth/me
Authorization: Bearer <access_token>
```

不要把 Token 发到聊天、工单或截图中。初始 admin 随机密码只在首次创建时输出，登录后立即通过 Client 或 `PUT /api/v1/auth/me/password` 修改。

## 正常权限上下文

`/me` 至少应确认：用户未删除、`current_org_id` 非空、存在组织成员角色；admin 通常还应有 `is_super_admin=true`。Task 会使用相同 JWT 并向 Auth `/me` 同步当前用户和租户。

首次部署后 admin 在 Client 的“管理中心 → 客户 SRM”提示权限不足，依次检查：

1. Auth 与 Task 的 `JWT_SECRET` 是否相同。
2. Client 实际连接的 Auth/Task 是否属于同一套环境。
3. `/me` 的 `current_org_id`、`is_super_admin`、`portal_org_role`。
4. 使用同一 Token 调用 `GET /api/v1/autotask/portal-accounts`。
5. Task 日志中 Auth `/me` 的 HTTP 状态和 `message_key`。

常见错误含义：

| message_key | 处理方向 |
| --- | --- |
| `errors.org.user_has_no_org` | 给用户设置当前组织和有效成员关系 |
| `errors.auth.token_invalid_or_expired` | 重新登录；核对 JWT secret、算法和机器时间 |
| `errors.auth.user_sync_failed` | 检查 Task 到 Auth 网络及 `/me` 响应 |
| `errors.autotask.permission_denied` | 检查组织角色和资源所属租户 |

Client 当前可能把后端 403 详情简化为“权限不足”，因此以 Postman/curl 的原始响应和服务日志为准。

## 账号运维

- 禁止多人长期共用 admin；内部验收可临时共用，验收结束应创建实名账号并最小授权。
- `RESET_ADMIN_PASSWORD=true` 只用于受控恢复；恢复后立即改回 false 并轮换密码。
- 删除或离职用户前转移其组织/Portal 资源所有权，撤销 refresh token 和外部密钥。
- 不通过 SQL 直接改密码哈希或伪造组织关系，除非 Auth 团队提供正式恢复脚本并有审计授权。
