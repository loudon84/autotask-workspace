# 配置秘密网络与防火墙清单

## 不得进入 Git 或文档

数据库 URL、JWT_SECRET、ENCRYPTION_KEY、Task Client Secret、MinIO Key、门户用户名/密码、Token、签名下载 URL、`.env`、Client 本地 endpoint 文件和运行 Artifact。

## 关键一致性

- Auth 与 Task 的 `JWT_SECRET` 必须完全相同，否则 Task 调 Auth `/me` 会失败。
- Task 的 `RPA_ENGINE_BASE_URL` 必须是 Task 进程可访问地址。
- Engine 的 `TASK_API_BASE_URL` 必须以 `/api/v1/autotask` 结束。
- 跨机器 Artifact 下载时，Task 的 `PUBLIC_BASE_URL`、`ARTIFACT_UPLOAD_BASE_URL`、`ARTIFACT_DOWNLOAD_BASE_URL` 不能使用 `127.0.0.1`。
- Client 构建时默认 Auth/Task 地址和安装后的高级 endpoint 配置都可能生效；排障时必须核对实际保存值。
- Portal URL 是业务网站地址；`credentialRef` 是凭据引用；`persist:...` 是浏览器 session partition，三者不是同一概念。

## 凭据模式

当前 `mock_env` 只适用于 development/test，并应同时限制 credentialRef、tenantId 和 portalAccountId。每增加一个新 Portal 凭据，在现有实现下通常需要更新 Engine 的受限环境配置并重启；生产必须改为集中凭据服务，不能继续扩展 `.env`。

## 端口

| 端口 | 用途 | 建议暴露范围 |
| ---: | --- | --- |
| 4510 | Auth | Client 与 Task 可达 |
| 4520 | Task | Client 与 Engine 可达 |
| 4610 | Engine | Task/运维可达；Client 非必需 |
| 5432 | PostgreSQL | 仅服务主机/数据库管理网 |
| MinIO API | Flow/Artifact | 仅 Engine、Task 和管理员 |

Windows 防火墙示例应由管理员按公司网段或主机组建立规则。即使内部使用，也不建议向所有网络配置文件永久开放数据库、MinIO 和 Engine 管理接口。
