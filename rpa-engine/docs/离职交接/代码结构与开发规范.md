# 代码结构与开发规范

## 目录结构

```text
src/nodeskclaw_rpa_engine/
  api/             FastAPI 应用与路由
  core/            配置、健康检查、结构化日志
  db/              会话和九张表模型
  flows/           Manifest、ZIP 策略和 Registry
  object_storage/  S3 兼容存储
  workers/         Worker、lease、Task Client、Outbox
  runtime/         Flow、浏览器、凭据、Artifact、错误处理
  task_api/        Task 依赖适配
  mock_srm/        独立演示服务
migrations/        Alembic
sql/               DBA 审阅的 dormant DDL
tests/             单元、API、契约和回归测试
scripts/           构建与受控演示脚本
postman/           Engine 入站接口集合
deploy/            systemd 等部署文件
```

## 分层规则

- API 路由只处理 HTTP 参数、依赖注入和响应；状态机放 Service，查询和锁放 Repository。
- 应用启动不得通过 SQLAlchemy 模型自动建表或迁移。
- Task 的 snake_case/camelCase 兼容集中在 schemas/client 适配层。
- Flow Registry 只使用精确 UUID/checksum，禁止“最新版本”隐式回退。
- 外部 HTTP 必须有超时并默认 `trust_env=False`；代理必须通过显式受控配置接入。
- Runtime 只给 Flow 暴露受控 `ctx`，Flow 不得自行启动浏览器或连接 CDP。

## 修改规则

- 已发布 Flow 不可变，修复必须新建 SemVer。
- ORM 变化必须同步模型、Alembic、dormant SQL、结构测试和文档。
- 新配置必须有安全默认值、校验、脱敏快照和测试。
- 回调必须考虑幂等、超时、重试和重启恢复。
- 路径使用 `pathlib.Path`，同时兼容 Windows 和 Linux。
- 不修改用户 `.env`，不把测试地址或凭据写入源码。

## 质量门禁

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m mypy
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m pip check
```

Windows pytest 若因临时目录 ACL 报 `WinError 5`，使用受控可写的独立 `--basetemp`，不要误判为业务失败。

## Git 与评审

- 提交前执行 `git status --short` 和 `git diff --check`。
- 禁止提交 `.env`、虚拟环境、缓存、Flow ZIP、Runtime 文件、Artifact、截图、Trace、下载文件和签名 URL。
- 不强制 push，不覆盖未知本地改动；提交说明使用简体中文。
- 评审重点是重复领取/写入、租约与终态一致性、秘密泄露、快照精确性、取消/重启安全和跨平台兼容。
