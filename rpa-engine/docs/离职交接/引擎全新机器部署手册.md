# RPA Engine 全新机器部署手册

本文只说明 Engine。Auth 和 Task 应已能够运行，PostgreSQL、MinIO/S3 和网络由管理员准备。

## 1. 部署前确认

- Python `3.12`、Git 已安装。
- Task 健康接口可访问。
- PostgreSQL 已创建数据库 `nodeskclaw_task`、角色 `task_user` 和空 Schema `rpa_engine`。
- MinIO/S3 bucket 已由管理员创建。
- Engine 主机可以访问 PostgreSQL、MinIO/S3、Task、Portal 和 Artifact 上传地址。
- 同一环境没有其他实例使用计划中的 `WORKER_ID`。

## 2. 拉取代码与安装依赖

Windows PowerShell：

```powershell
cd D:\AutoTask-Workspace
git clone -b v0.1 https://github.com/loudon84/copilot-rpa.git rpa-engine
cd .\rpa-engine
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install ".[dev]"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pip check
Copy-Item .env.example .env
```

Linux 常驻部署使用仓库现有 `docs/LINUX_DEPLOYMENT.md`，必须采用非 root 服务用户、单 Uvicorn 进程和独立 Runtime/浏览器目录。

## 3. 配置安全基线

第一次启动先关闭领取任务：

```env
APP_ENV=test
APP_HOST=0.0.0.0
APP_PORT=4610
RPA_ENGINE_PUBLIC_BASE_URL=http://<Task可访问的Engine主机>:4610

DATABASE_ENABLED=true
DATABASE_URL=postgresql+asyncpg://task_user:<密码>@<数据库主机>:5432/nodeskclaw_task
DATABASE_SCHEMA=rpa_engine

MINIO_ENABLED=true
MINIO_ENDPOINT_URL=http://<对象存储主机>:<端口>
MINIO_ACCESS_KEY=<从秘密保管系统注入>
MINIO_SECRET_KEY=<从秘密保管系统注入>
MINIO_BUCKET=rpa-flow-packages

TASK_API_BASE_URL=http://<Task主机>:4520/api/v1/autotask
TASK_AUTH_MODE=none

WORKER_ENABLED=false
WORKER_LEASE_ENABLED=false
RUNTIME_ENABLED=false
CREDENTIAL_RESOLVER_MODE=disabled
```

`.env` 不得提交 Git。生产环境不能使用 `TASK_AUTH_MODE=none` 或 `mock_env` 凭据解析器。

## 4. 首次迁移

以下操作只能由获授权的管理员在确认连接目标后执行。Engine 应用启动不会自动迁移。

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
```

期望 revision：

```text
20260713_0001
```

全新空 Schema 使用 `upgrade head`。如果环境已经存在九张 Engine 表，禁止执行初始 upgrade；先做结构漂移检查，再由 DBA 决定是否 `stamp 20260713_0001`。

## 5. 分阶段启动

第一阶段只验证服务和 Registry：

```powershell
.\.venv\Scripts\python.exe -m nodeskclaw_rpa_engine
```

确认 `/health/live`、`/health/ready` 均为 200，再停止服务，将：

```env
WORKER_ENABLED=true
WORKER_LEASE_ENABLED=false
RUNTIME_ENABLED=false
```

第二阶段只验证 Worker 注册和心跳。Task 应显示 Worker 在线，但 Engine 不领取 Run。

第三阶段准备 Runtime 和受控测试凭据：

```env
RUNTIME_ENABLED=true
WORKER_LEASE_ENABLED=false
```

确认 Runtime 目录可写、浏览器已安装、精确 Flow/Binding 和唯一测试 Run 已准备后，最后才设置：

```env
WORKER_LEASE_ENABLED=true
```

## 6. 部署验收

- `/health/live` 返回 200。
- `/health/ready` 返回 200，所有 `required=true` 依赖均为 `healthy`。
- Engine OpenAPI `/docs` 可访问。
- Worker 注册与心跳正常。
- Flow 查询接口可用。
- 受控测试完成一条 SUCCESS，Task、Run、attempt 终态一致。
- 截图可预览，XLSX 等 Artifact 可下载。
- Engine 停止后 Worker 能进入 OFFLINE。
