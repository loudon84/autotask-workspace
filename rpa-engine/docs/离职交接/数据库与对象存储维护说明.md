# 数据库与对象存储维护说明

## 1. 数据库基线

- PostgreSQL 数据库固定为 `nodeskclaw_task`。
- Task 使用 `public` Schema。
- Engine 使用 `rpa_engine` Schema。
- Engine 连接显式使用 `rpa_engine,public` search path，不修改角色的全局 search path。
- Engine Alembic revision 为 `20260713_0001`，版本表位于 `rpa_engine.alembic_version`。
- 应用启动不执行 `create_all`、迁移、stamp、种子或 DDL。

九张 Engine 表为：

```text
rpa_flows
rpa_flow_versions
rpa_flow_validation_runs
rpa_flow_release_audits
rpa_worker_instances
rpa_execution_attempts
rpa_callback_outbox
rpa_browser_profiles
rpa_cdp_endpoints
```

Artifact 元数据属于 Task；Engine Runtime 只负责记录本地文件、申请上传地址、上传并调用 Task 元数据接口。

## 2. 首次初始化边界

DBA 先创建数据库、角色和空 `rpa_engine` Schema，再由获授权人员执行：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
```

已有九张 Engine 表时禁止直接 upgrade。必须先做结构漂移检查，再由 DBA 决定 stamp。不得通过删除 `alembic_version` 或重建 Schema 解决版本不一致。

## 3. 备份原则

Task 和 Engine 共享数据库，备份必须覆盖 `public` 与 `rpa_engine`，并与对象存储形成一致恢复点。示例命令只供 DBA 在获授权窗口使用：

```text
pg_dump --format=custom --file=<备份文件> nodeskclaw_task
pg_restore --list <备份文件>
```

密码通过安全提示、`.pgpass` 或 Secret Manager 提供，不写在命令、脚本或文档中。

备份记录至少包含：数据库版本、备份时间、提交 SHA、Alembic revision、对象存储快照时间、负责人和校验结果。

## 4. 恢复原则

1. 先停止 Task 写入和 Engine lease。
2. 确认没有 RUNNING Run。
3. 恢复 PostgreSQL 和对应时点的对象存储。
4. 检查 `rpa_engine.alembic_version`、九张表、Flow 版本记录及对象键一致性。
5. 先关闭 lease 启动 Engine，验证 Registry 包可读取。
6. 再验证 Worker 注册和唯一测试任务。

只恢复数据库、不恢复 Flow ZIP 会造成 Registry 元数据存在但包不可读；只恢复对象存储、不恢复数据库会产生孤立对象。

## 5. MinIO/S3 管理

- bucket 必须由管理员预先创建，Engine 不会创建。
- 启用服务端加密、版本控制、生命周期和访问日志时，应由存储管理员记录策略。
- 禁止公开 bucket。
- Engine 使用的 Key 只授予所需 bucket/prefix 权限。
- 签名 URL 短时有效，不能写入日志或工单。
- 删除历史 Flow 对象前必须核对 Registry、Binding 和审计保留要求。

## 6. 定期检查

- PostgreSQL 备份是否成功并可恢复。
- 数据库容量、连接数、慢查询和锁。
- Outbox 未发送/重试/死信数量。
- MinIO/S3 容量、版本和生命周期执行情况。
- Registry 版本记录与对象存在性抽检。
- Artifact 保留周期是否符合业务和合规要求。
