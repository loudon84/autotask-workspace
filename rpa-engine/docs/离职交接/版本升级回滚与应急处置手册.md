# 版本升级、回滚与应急处置手册

## 1. 升级前

1. 记录当前 Git SHA、Engine 版本、Alembic revision 和 `.env` 配置项清单。
2. 确认没有 RUNNING Run，暂停 Task 新任务或关闭 lease。
3. 完成 PostgreSQL 和对象存储一致备份。
4. 阅读目标版本迁移说明，确认是否需要新浏览器版本或配置项。
5. 在独立测试环境通过 Ruff、mypy、pytest、`pip check` 和端到端冒烟。

## 2. 升级顺序

```text
关闭 lease
-> 优雅停止 Engine
-> 拉取指定提交
-> 安装依赖
-> 管理员执行获批迁移
-> 安装匹配的 Playwright 浏览器
-> 关闭 Worker/Runtime 启动并检查 ready
-> 开启 Worker 注册和心跳
-> 开启 Runtime
-> 最后开启 lease
-> 唯一专用任务验收
```

Git 更新只使用明确分支和 `--ff-only`。不要在有未确认本地改动时强行 reset 或覆盖。

## 3. 代码回滚

- 回滚到已验证的提交 SHA，不使用模糊的“最新稳定版”。
- Python 依赖和 Playwright 浏览器版本必须与目标提交重新对齐。
- 如果升级包含不可逆数据库迁移，不能只回滚代码；按获批数据库恢复方案执行。
- 回滚后先关闭 lease验证 health/Registry/Worker，再运行专用任务。

## 4. Flow 回滚

已发布 Flow 不可覆盖。Registry 回滚后还必须在 Task 中把 Binding 显式切换到旧版本精确 UUID/checksum。历史 Task/Run 保持原快照，不应被批量改写。

## 5. 应急停机条件

出现以下任一情况应立即阻止新 lease：

- 重复执行或疑似重复外部写入。
- Worker ID 冲突或多个实例领取同一类任务。
- Task 与 Engine 终态持续不一致。
- Callback Outbox 大量积压或 Task 无法去重。
- Artifact 泄露、凭据泄露或签名 URL 被记录。
- 数据库/对象存储出现数据损坏或容量耗尽。
- Portal 页面变化导致 Flow 大范围误操作。

## 6. 应急步骤

1. 在配置或调度入口关闭新 lease。
2. 保留日志、Run/Lease/attempt ID、事件和 Artifact，不删除证据。
3. 对运行中任务优雅 drain；只有确认无法安全退出时才升级处置。
4. 核对外部系统实际业务结果，禁止盲目重试。
5. 轮换可能泄露的秘密并吊销旧凭据。
6. 修复后在隔离环境复现，通过唯一专用任务再恢复。
7. 记录原因、影响、时间线、处置人和防复发措施。

## 7. 禁止事项

- 不在运行中删除 Runtime 目录或浏览器 profile。
- 不直接修改 Task/Engine 终态来掩盖故障。
- 不删除失败 Run、Outbox 或审计记录。
- 不在未确认外部副作用时自动 retry。
- 不把生产秘密复制到测试环境或聊天工具。
