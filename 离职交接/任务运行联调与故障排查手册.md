# 任务运行联调与故障排查手册

## 1. 标准联调顺序

1. 确认 Auth、Task、Engine health 均为 200。
2. 确认 Flow 已发布且 Binding 精确校验 `valid=true`。
3. 确认 Worker 为 ONLINE、空闲且能力匹配。
4. 清理或取消无关 `QUEUED` Run。
5. 只创建一个专用 Task 并启动。
6. 轮询 Task Run 详情，观察 `QUEUED -> RUNNING -> 终态`。
7. 检查 Run Events、Artifacts、下载地址和 Engine attempt/Outbox。

## 2. 正常运行应出现的调用

```text
register -> heartbeat -> lease -> renew
-> event
-> artifact upload-url -> signed PUT -> artifact metadata
-> finish
```

不要用 Postman 手工模拟 Engine 的 lease、renew、event、Artifact 或 finish 回调来代替端到端验收。

## 3. 状态含义

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| `DRAFT` | 任务尚待用户补充输入 | 填写完整后再运行 |
| `QUEUED` | 等待 Worker 领取 | 检查 Worker、lease 和队列阻塞 |
| `RUNNING` | 已领取并执行 | 观察 renew、事件和当前步骤 |
| `SUCCESS` | Flow 与 finish 成功 | 核对输出和 Artifact |
| `FAILED` | 确定失败 | 根据 errorCode 判断业务/系统错误 |
| `WAITING_HUMAN` | 需要人工处理 | 当前不能恢复原浏览器会话 |
| `CANCELLED` | 已取消 | 不应再被 lease |

## 4. 常见故障矩阵

| 现象 | 优先检查 |
| --- | --- |
| Client 显示“权限不足” | 4510 `/auth/me` 的 `current_org_id/is_super_admin`；4510/4520 JWT Secret；Task Backend URL；完整 403 `message_key` |
| Binding 保存 500 | Engine ready、Flow 是否 PUBLISHED、UUID/checksum、Task 到 4610 网络 |
| Worker OFFLINE | `WORKER_ENABLED`、Task 地址、register/heartbeat 日志、重复 Worker ID |
| Run 一直 QUEUED | lease 是否开启、Runtime 是否开启、前序无效 QUEUED Run、能力和快照字段 |
| Run 立即 FAILED | Run Events、Engine attempt errorCode、Flow 包加载、凭据作用域、浏览器 channel |
| `FLOW_UNHANDLED_ERROR` | Engine 脱敏 traceback、Flow 未捕获异常；不要只看 Task 的通用错误文案 |
| `PermissionError`/`EACCES` | Runtime/浏览器目录所有者、并发进程、杀毒软件和文件占用 |
| Artifact 上传失败 | Task 上传 base URL、签名 URL 对 Engine 可达性、对象存储权限 |
| Artifact 远程无法预览/下载 | Task download/public base URL 是否是 Client 可达地址，不能返回 127.0.0.1 |
| 门户登录失败 | credentialRef、tenantId、portalAccountId、Portal URL、验证码和账号状态 |

## 5. 403 权限诊断

使用登录返回的 `data.access_token` 调用：

```http
GET /api/v1/auth/me
Authorization: Bearer <access_token>
```

确认 `current_org_id` 非空且 admin 的 `is_super_admin=true`。再用同一 Token 调 Task Portal 列表。只转发错误 JSON，不转发 Token。

常见 `message_key`：

- `errors.org.user_has_no_org`：用户没有组织。
- `errors.auth.token_invalid_or_expired`：JWT Secret、Token 或 endpoint 不一致。
- `errors.auth.user_sync_failed`：Task 无法从 Auth 同步用户。
- `errors.autotask.permission_denied`：Portal 授权或 Task 用户缓存异常。

## 6. 结果不明确时

如果 Portal/ERP 写操作发生超时、断连、进程崩溃或 finish 未确认：

1. 禁止自动重试。
2. 记录 Task/Run/Lease/attempt ID 和时间。
3. 查询外部系统是否已经完成业务写入。
4. 核对 Outbox 与 Task 终态。
5. 由业务负责人决定补偿、人工确认或重新运行。

这条规则优先于“尽快恢复演示”。
