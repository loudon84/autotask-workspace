# 已知限制、风险与后续开发清单

## 1. 生产阻断项

| 优先级 | 项目 | 当前状态 | 完成标准 |
| --- | --- | --- | --- |
| P0 | Worker 生产鉴权 | `TASK_AUTH_MODE=none` 仅限测试；service-account Token exchange 未实现 | 服务账号短期 Token、轮换、401 恢复和审计完成 |
| P0 | 生产凭据服务 | `mock_env` 只支持单个 Portal 精确作用域 | 接入受管凭据服务，按租户/Portal 授权并可轮换 |
| P0 | Flow 执行隔离 | Python Flow 在 Engine 进程内 | 子进程或容器隔离、硬超时、资源限制、孤儿清理 |
| P0 | Artifact 可靠投递 | 上传和 metadata 为直接调用 | 本地保留、Outbox、幂等、重试、重启恢复和清理 |
| P1 | 调度队列 | HTTP lease 兼容层 | 能力过滤、ACK、可见性超时、重试、死信和监控 |
| P1 | WAITING_HUMAN 恢复 | Type-A 结束后关闭会话 | 安全恢复原会话、超时、归属和审计机制 |
| P1 | Task Callback 去重 | Engine 已发送稳定幂等键 | Task 持久去重并按 leaseId 拒绝陈旧 FINISH |

## 2. 运维风险

- 同一 Worker ID 多实例会造成状态和恢复冲突。
- Runtime 整个 Flow 重试可能重复外部副作用。
- Task Artifact download/public base URL 配错会导致远程 Client 预览或下载失败。
- Portal DOM、验证码或下载行为变化会使已有 Flow 失效。
- PostgreSQL 与对象存储未做一致备份时无法完整恢复 Registry。
- Linux 目录所有者不正确会产生 `EACCES`；Windows 杀毒或文件占用可能产生 `WinError 5`。

## 3. 产品与界面待办

- Client 完整 Flow Registry 图形页面仍需完善，包括上传进度、校验详情、发布确认和版本生命周期。
- 任务状态实时更新需要稳定轮询或推送机制，并明确断线重连。
- Artifact 预览应覆盖大图、XLSX 下载、过期 URL 重新获取和失败提示。
- Portal、模板、Binding 和任务的权限模型应在 Client 中展示真实权限，而不是只在 403 后降级。

## 4. 测试待办

- Linux 实机端到端运行及长期稳定性。
- Task/Engine 重启、断网、lease 过期和 callback 重放测试。
- 多 Worker、多租户和能力路由测试。
- 大文件 Artifact、磁盘满、MinIO 中断和恢复测试。
- Portal 页面版本变化及选择器兼容测试。
- 数据库与对象存储联合恢复演练。

## 5. 不应被误报为已完成

- “能在测试环境跑成功”不等于生产鉴权、隔离、幂等和恢复已经闭环。
- `WAITING_HUMAN` 不等于人工输入后原流程会继续。
- Flow 发布成功不等于 Task Binding 已切换。
- Engine finish 成功不等于 Artifact 一定可靠落库。
- health/live 为 200 不等于 Engine 已准备领取任务；必须看 health/ready。
