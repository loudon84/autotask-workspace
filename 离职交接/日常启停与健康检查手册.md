# 日常启停与健康检查手册

## 1. 启动前检查

1. PostgreSQL 和 MinIO/S3 已运行。
2. Task 健康且 Engine 主机能访问其 API。
3. Runtime 目录和 Playwright 浏览器目录归 Engine 运行用户所有。
4. 没有另一个相同 `WORKER_ID` 的实例。
5. 启用 lease 前，Task 队列没有无关或缺少 Flow 快照的 `QUEUED` Run。

## 2. Windows 启动

```powershell
cd D:\AutoTask-Workspace\nodeskclaw-rpa-engine
.\.venv\Scripts\python.exe -m nodeskclaw_rpa_engine
```

不要使用多个 Uvicorn worker。Worker、缓存和 lease 轮询按单进程设计。

## 3. Linux 启动

```bash
sudo systemctl start nodeskclaw-rpa-engine.service
sudo systemctl status nodeskclaw-rpa-engine.service
sudo journalctl -u nodeskclaw-rpa-engine.service -f
```

## 4. 健康检查

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:4610/health/live
Invoke-RestMethod http://127.0.0.1:4610/health/ready
```

`live=200` 只表示进程存活。`ready=200` 才表示所有必需依赖可用。

| 依赖 | 何时必需 | 常见异常 |
| --- | --- | --- |
| `database` | 启用数据库/Worker | 连接串、权限、Schema、网络 |
| `objectStorage` | 启用 MinIO/Runtime | endpoint、bucket、密钥、网络 |
| `taskApi` | Worker 或 Runtime 启用 | Task 地址、Task 未启动、代理 |
| `runtimeFilesystem` | Runtime 启用 | 目录不存在、权限、磁盘空间 |

Worker 观察接口：

```http
GET /api/v1/workers
GET /api/v1/workers/{workerId}
X-Actor-Id: <审计标识>
```

## 5. 正常停止

1. 确认没有 `RUNNING` Run。
2. 将新任务入口暂停或暂时关闭 lease。
3. Windows 窗口按 `Ctrl+C`；Linux 使用 `systemctl stop`。
4. 等待 Worker 完成 `DRAINING -> OFFLINE`。
5. 确认没有遗留浏览器进程和被占用的 Runtime 目录。

不要直接结束正在执行真实门户写操作的进程。若执行结果不明确，必须先记录 Task ID、Run ID、Lease ID、当前步骤和时间，再按应急流程处理。

## 6. 每日检查

- health/live 与 health/ready。
- Worker 在线状态、心跳和占用槽位。
- QUEUED、RUNNING、WAITING_HUMAN、FAILED 数量。
- Callback Outbox 是否存在持续重试或死信。
- Artifact 上传/下载是否成功。
- Runtime 磁盘空间和异常残留目录。
- 日志中是否出现 401/403/409/5xx、lease 过期、浏览器启动失败或敏感信息。

## 7. 重启后检查

同一 Worker ID 遗留的 `LEASED`/`RUNNING` attempt 会被 Engine 恢复为 `ABANDONED` 并写入 FINISH Outbox。重启后不要立即重跑业务任务；先确认 Task 已收到一致终态，并核实外部系统是否已经产生副作用。
