# 配置项与凭据管理说明

## 1. 配置来源

Engine 使用环境变量和本地 `.env`。服务器部署优先使用受限 EnvironmentFile 或 Secret Manager。配置项大小写不敏感；`.env.example` 只提供空值和安全默认值。

以下内容永远不得进入 Git、聊天、工单截图或普通日志：

- `DATABASE_URL`
- `MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`
- `TASK_CLIENT_SECRET`
- Portal 用户名和密码
- JWT、Token、Authorization Header
- 对象存储签名 URL

## 2. 核心配置组

| 配置组 | 关键变量 | 说明 |
| --- | --- | --- |
| 服务 | `APP_ENV`、`APP_HOST`、`APP_PORT`、`RPA_ENGINE_PUBLIC_BASE_URL` | 对外地址必须可被 Task 访问 |
| Registry | `FLOW_PACKAGE_*` | 包大小、文件数、压缩比和签名 URL TTL |
| 数据库 | `DATABASE_ENABLED`、`DATABASE_URL`、`DATABASE_SCHEMA` | 数据库名固定 `nodeskclaw_task`，Schema 固定 `rpa_engine` |
| 对象存储 | `MINIO_ENABLED`、endpoint、key、bucket、region | bucket 必须预先存在 |
| Task | `TASK_API_BASE_URL`、`TASK_AUTH_MODE`、超时 | URL 必须包含 `/api/v1/autotask` |
| Worker | `WORKER_ENABLED`、`WORKER_ID`、能力、心跳、轮询 | 同一 Worker ID 只能运行一个实例 |
| Runtime | `RUNTIME_ENABLED`、缓存/工作目录、超时、Trace、输出上限 | 缓存目录与工作目录不能相同 |
| 凭据 | `CREDENTIAL_RESOLVER_MODE`、Mock 作用域 | `mock_env` 仅限 development/test |

## 3. 强制依赖关系

- `WORKER_LEASE_ENABLED=true` 要求 `WORKER_ENABLED=true`。
- `WORKER_ENABLED=true` 要求 `DATABASE_ENABLED=true`。
- Worker 能力必须至少包含 `PLAYWRIGHT_CDP` 和 `BROWSER_SESSION_MANAGED`。
- `RUNTIME_ENABLED=true` 要求 `MINIO_ENABLED=true`。
- `mock_env` 只允许 `APP_ENV=development|test`，并且必须完整填写 credentialRef、用户名、密码、tenantId 和 portalAccountId。
- `service_account` 模式要求 Client ID/Secret，但当前 Token exchange 尚未实现，不能作为已完成的生产能力。

## 4. Portal 凭据规则

Client Portal 表单中的：

- `credentialRef` 是凭据引用。
- `clientSessionPartition`（例如 `persist:...`）是 Electron 浏览器会话隔离标识，不是凭据引用。
- `loginAccount` 是业务展示字段，不应当承担秘密存储。

当前 `mock_env` 只允许一个精确组合：

```text
credentialRef + tenantId + portalAccountId
```

新建 Portal 后，即使登录账号相同，只要 Portal ID 改变，也要更新 Engine 受限配置并重启。该限制是测试兼容方案，不是生产凭据架构。

## 5. 轮换流程

1. 由秘密负责人生成或接收新秘密。
2. 在 Secret Manager 或服务器受限配置中更新，不修改源码。
3. 在没有运行中任务时优雅重启 Engine。
4. 先关闭 lease 验证 ready、Worker 注册和目标 Portal 凭据解析。
5. 再开启唯一专用任务完成冒烟。
6. 删除或吊销旧秘密，记录轮换日期和责任人。

不要为了排障把秘密打印到控制台。只记录配置项名称、是否存在、作用域是否匹配和错误类别。
